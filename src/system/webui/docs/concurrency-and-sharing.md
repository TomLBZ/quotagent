# 两个人同时干活（乐观并发）/ 分享 / 导出模板可配

<!-- 预算：12 KB。口径真源：`docs/design/29-webui-gui-app.md` §3（注册面）与 §10（导出/附件）；本文件讲这三件事的**机制与判据**（真源同样在本文件，29 那份不再重复）。复跑：`python3 tmp/p9-verify.py`（截图见 `tmp/p9-shots/`）。 -->

本批给 GUI 补上三件"多人一起干活真的需要"的事：**不互相覆盖**（乐观并发）、**能把事分享出去**、
**导出列可配且跨浏览器仍在**。三件都在**外壳（机制）**这一层，插件只**声明**；三件都**不写账本**。

## 1. 乐观并发（对象版本 / 指纹）

用户口径：「两个人同时改同一个东西时，不能后写把前写盖掉 —— 要**明确拒绝**，并说清**谁在何时改了什么**，
让人**能重做**」。

### 1.1 分工：插件只声明"这是什么对象、写进去的是什么"

`action.concurrency = {object_class, label, id_field | object_id(ctx, input), state(ctx, input)}`：

- `object_class`（形状同 `OBJECT_KIND_RE`）+ `label`（人话：界面上与拒绝原因里都用它）；
- 对象 id：`id_field`（入参里指对象 id 的字段名）**或** `object_id(ctx, input)`（插件自己算，
  例如"我方对这份包的报价草稿" = `包#行项目集合`）；
- `state(ctx, input)` = **这次保存后对象的权威新状态**（**扁平 字段 → 标量**，由插件从它自己的事实/入参给出）。

外壳对它**只做三件事**：取指纹（`sha256`）、逐字段算差异、跟已记录的版本比 —— **它不认识任何字段的业务
含义**（所以同一套机制同时保护得了报价草稿、变更单回应、比价权重这类完全不同的东西）。

### 1.2 外壳自动加一个**只读**的版本字段

声明了 `concurrency` 的动作，注册面**自动**给它加上 `expected_version`（`readonly:true` + `version_field:true`）：
界面把你**打开这一页时看到的版本**填进去。来源顺序（都有出处，不猜）：

1. 插件在 `editable_defaults` / 行里给的值；2. 行的 `version`（行内动作、批量、右键菜单）；
3. 打开它的那块面板的 `data.version`（可编辑表格"提交编辑"这一路）；
4. 页面上声明 `version_for:'<动作 id>'` 的面板；5. 对象页页头的 `version`。

**版本形状** = `{rev, fingerprint, at, by, label, fields}`（`host.versions.current(side, class, id)` 给的就是它）；
面板用 `version_for` 说明"这一版是给哪个动作用的"，行用 `version` 说明"这一行的那一版"。

### 1.3 判据（**不后写覆盖前写、也不静默吞掉**）

保存前在**动作的服务端一半执行之前**比对（拒绝 ⇒ 账本与待办件**零新增**）：

| 情形 | 判据 | 结果 |
|---|---|---|
| 这个对象还没有版本记录 | 首次 | 放行；成功后记 `rev 1` |
| `expected_version` 与记录**对得上**（指纹或 `rev:<N>`） | 看过了 | 放行；成功后 `rev+1` |
| 没带版本，**但这次要写的内容与现在一模一样** | 没有改动 | 放行（谈不上覆盖；不制造新版本） |
| 没带版本，**内容会变** | 没看过就改 | **拒绝** `object-changed`（安全默认） |
| 带了版本但**对不上** | 别人先改过 | **拒绝** `object-changed` + 差异 |

拒绝回执的 `result.conflict`（**"谁在何时改了什么"就在这两个键里**）：

- `since` = 自你那一版以来的**逐字段改动**（`{field, from, to, by, at, rev}`）；你那一版已经不在保留的
  改动历史里时 `since_known:false`，回执**如实说明**（不编"谁改的"）；
- `mine` = **你要写什么 vs 现在是什么**（逐字段）。
- 例子（真跑输出）：`「我方对这份包的报价草稿」已经被别人改过：现在是 rev 4，最后改动 human:linmei @
  2026-09-22T22:29:34.015Z；你手上那一版是 sha256:9a3f…`。

### 1.4 界面（冲突不是"失败了"四个字）

冲突弹在同一张表单里（`assets/app.js#wireConflict`）：一张**事实表**（字段 / 改前 / 改后 / 谁改的 / 何时 /
哪一版）+ 三个出口：**带上最新版本重做**（重新读这一页、把最新版本带进表单，**你填的值留着**）、
刷新看最新的、放弃这次保存。`Ctrl/⌘+Enter`、行内动作、批量、右键菜单打开的表单都走同一条路。

### 1.5 存储与边界（**不是账本**）

`<ui_shared>/webui/object-versions/<侧>.json`（目录 **0700** / 文件 **0600**、原子写、有界：对象 ≤ 400 /
每对象历史 ≤ 12 / 字段 ≤ 40 / 值 ≤ 160 字符；超出**丢掉并如实计数**在 `dropped` 里）。**按侧隔离**。
**它不进账本**：版本/指纹是"谁看到过哪一版"的**运营状态**，不是合同事实（写进账本会改事件类型目录、
证据包哈希与审计取证语义 —— 与协作面/名册/附件同源的理由）。

本批**受保护的对象**（可在 `/api/ui/surface` 的 `versions.guarded_actions` 里逐条对账）：

| 动作 | 对象 | 保护的是什么 |
|---|---|---|
| `quote.draft`（供应商） | `quote-draft` = 包 id（这份包一份草稿） | 两个人各自备"这份包的报价"时不许互相盖价（谁改的是哪些行由差异表逐行给出） |
| `exchange.change-respond`（供应商） | `change-response` = 变更单 id | 同一份变更单的回应不许被后一份悄悄顶掉 |
| `compare.save-weights`（承包商） | `compare-weights` = `current` | 本侧那组比价权重不许被后改的人盖掉 |

**如实登记的边界**：① 对象 id 由插件声明 —— 声明成"包 + 行项目集合"时，**只改一行**再提交会落到
"那一行的行项目集合"这个对象上（第一次保存按首次处理）；② 版本库按侧分文件 ⇒ 跨侧并发不进同一份记录
（跨侧本来就没有共享的可编辑对象）；③ 未登录时侧为空（记在 `anon` 那一份），拒绝路径照样不含糊；
④ **不是锁定**：版本对得上就放行（两个人**先后**带各自的版本保存都能成功 —— 这是乐观并发，不是抢锁）。

## 2. 把事**分享出去**：深链 + 「对方需要什么身份/侧」+ 邮件正文

用户口径：「站内复制链接不够 —— 要能把事**分享给同事/发邮件**，并**告诉我对方需要什么身份才能看**；
越侧打开要**如实拒绝**」。

1. **入口是一个动作**（`system/webui-share` 的 `share.object`；对象页页头「分享（含邮件正文）」，也在工具栏
   与命令面板里）。它**不写账本、不落文件、不发邮件** —— 只把地址与前提拼成一段人能直接用的文字
   （`ledger_added` 恒为 0；验证脚本对拍两侧账本 md5）。
2. **产出三样**：
   ① **可复制深链** `/app/<view>/<kind>/<id>/`（相对路径由服务端给，**绝对地址由界面用 `location.origin`
   拼** —— 服务端不猜主机名）；
   ② **需求清单**：要不要登录、属于**哪一侧**、这个对象**在对方那侧能不能看**、对方从**哪个视角**能打开；
   ③ **邮件正文**（主题 + 逐行正文 + `{{LINK}}` / `{{ALT_LINKS}}` 令牌，界面换成绝对地址 ⇒ 一键复制即可粘贴）。
3. **"对方能不能看"由插件声明**（`data.object.share = {visibility:'both'|'side', other_side_view?, requirements?, note?}`）：
   交付件写 `both`、本侧内部件写 `side`（对方看不到）。**插件没声明时界面不替它断言**，如实说
   "无法断言，请让对方在他那一侧打开试试"。
4. **跨视图链接只在"确实声明过这个对象类"的视角上给**（`surface.objectKindsFor`），并写明"能看的前提是
   那个对象在那侧的事实里存在"。
5. **越侧打开如实拒绝**（不是白屏、也不是"能看"）：对象页对不在本侧投影里的 id 返回 `found:false` +
   有名原因（如 `po-not-delivered-to-you`）；分享同一条地址时弹层**照样如实说**未命中。本视图没有声明的
   对象类 ⇒ **明确拒绝** `object-kind-not-in-this-view` 并列出可分享的对象类。

## 3. 导出模板**可配**：列选择 = 个人偏好（跨浏览器仍在）

用户口径：「导出不能全员一套列 —— 每个人要的列不同，而且**换浏览器还得是这套**」。

1. **列是声明**：`surface.report({… columns:[{key,label}]})` —— 插件给出"这份导出有哪些列"（**元数据**，
   ≤ 40 列）；**内容仍由插件自己的动作生成**（谁的事实谁导出，外壳不生成内容）。
2. **列选择是偏好**：机制动作 `export.columns`（`system/webui-export`）把**你勾掉的列**按**会话身份**落
   `<ui_shared>/webui/export-prefs.json`（目录 0700 / 文件 **0600**、原子写、有界：身份 ≤ 64 / 每身份 ≤ 24
   份导出 / 每份 ≤ 40 列）。**不是账本**（列选择是你自己的看法，不是业务事实）。
   界面入口：每个带 `columns` 的导出在「导出 / 打印」区多一个「列（N/M）」按钮（勾选框弹层）；视图上还有一块
   「导出模板（列选择）」面板（逐行给当前选择 + 行内动作）。
3. **导出时按偏好过滤**：`host.report(spec)` 按**当前会话身份**读回偏好，只保留你选的列（**顺序按声明的
   顺序**），并在导出结果里自述 `columns_pref`（report id / 保存时刻 / 来源）+ `columns_used` /
   `columns_dropped` / `columns_available`（预览里逐列可核对）。选出来的列**一个都不在** ⇒ **如实拒**
   `report-columns-empty`（不偷偷导全表）。
4. **`report_id` 留空 = 只读**：`export.columns` 在 `report_id` 为空时只回"我现在这套列"（不写任何东西）——
   对象页上没有那块面板时，界面用它把「列（N/M）」填对（未登录 ⇒ `identity-required`）。
5. **换浏览器/换设备仍在**：读回同一份 0600 文件（按身份）⇒ 第二个浏览器、另一台设备都是这套列；
   **身份之间互不可见**（另一身份导出仍是全部列）。复跑证据：`tmp/p9-verify.py` 的 ⑤.7/⑤.8。
