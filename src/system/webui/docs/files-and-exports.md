## 1. 在界面上怎么用（不看文档也能上手）

1. **打开一个对象**：RFQ 包 / 报价 / 变更 / 采购单 PO 的对象页
   （如 `/quotagent/app/contractor/po/po-0001/`、`/quotagent/app/supplier/package/pkg-g1/`；
   深链从列表里每一行的「打开 →」复制）。
2. **传文件**：在「附件」面板里把文件**拖进虚线方块**，或点「选择文件」（可多选）。
   上传前先选「这个文件给谁看」：
   - **交付件（对方能看到并下载）**——RFQ 包、报价、回签的 PO 这类交换件；
   - **本侧内部件（对方永远看不到）**——内部核算依据、内部意见。
3. **看与下**：文件表里每行给 文件名 / 大小 / 上传人 / 时间 / sha256（点「复制」拿完整值对账）/
   给谁看；点文件名或「下载」就下载（响应头带 `x-attachment-sha256`，可当场核）。
4. **删**：行尾「删除（留痕）」→ 走动作表单（要填附件 id —— 从行里预填好的那个、可写一句理由）→
   确认后**留痕**：索引留墓碑（谁删的、什么时候）、原件进 `trash/`、`journal.jsonl` 记一行；
   对方在列表里看到的也是墓碑，不是静默消失。**只能删自己上传的**。
5. **导出 / 打印**：对象页工具栏下的「导出 / 打印」区里每个格式一个按钮：
   - `导出 CSV` = 一份表格文件（浏览器直接下载）；
   - `打印 / HTML` = 一份**自带样式的可打印文档**，弹出预览 + 「打印」（浏览器打印对话框，可另存 PDF）
     +「下载这份文件」。
   本批三种：**采购单 PO**（承包商）、**RFQ 包**（双方）、**比价表**（承包商）。
6. **状态栏「附件」**：本侧附件数 / 已删数 / 存储权限（应当是 `0600`）一眼可核；工作台首屏还有一块
   「附件存储（文件交换的落点）」面板给出落点、上限、对象类策略与"为什么不是账本"。

### 1.1 供应商侧的采购单（PO 投递 / 回签）—— 回签件就挂在 PO 上

1. **收到**：承包商「发 PO（人签）」的同一次动作会把这张 PO **同步投递**出去（两侧账本各一条 `po/distributed`
   + 交换面信封）。供应商登录后在**供应商道 ›「发给我的采购单」**看到它：PO id / 行数 / 金额 / 签发人 /
   签发时刻 / 投递时刻 / 追溯链 / 回签状态；点行内「打开 →」进对象页 `/app/supplier/po/<po-id>/`。
2. **逐行核**：对象页上「采购单逐行明细」给出 行项目 / 量 / 单价 / 行金额 / **单价基准**（中标报价条目）/
   追溯模式；「执行前提」给出 送货地址 / 交期窗口（承包商发 PO 时填的；**没填就如实写"对方没给"**）、
   包版本 / 币种 / 报价截止（来自本侧包事实）。
3. **下载 / 打印**：对象页「导出 / 打印」区里 `导出 CSV` 与 `打印 / HTML`（自带样式的可打印文档 + 预览层里的
   「打印」「下载这份文件」）。内容 = **本侧账本** `po/distributed` 的行 + 追溯链 + 账本行号，表头还带投递时刻、
   送货地址/交期与回签状态（打印出来能逐行对回账本）。
4. **挂回签件**：同一对象页的「附件」面板就是**回签件该去的地方**——把签章 PDF/扫描件拖进来（选「交付件」），
   承包商在**同一张 PO** 的对象页里就能看到并下载（sha256 可当场核）。
5. **回签**：工具栏「确认收到采购单（人签）」（或列表行内点它）→ 填 `po_id`（对象页会自动带）+ 署名
   （**必须是你的会话身份**，服务端会核）+ 备注 → 「下一步：确认」→「确认执行」。落账：**双方账本各一条
   `po/acknowledged`**（回签人 = 你的会话身份）；同一人重复回签幂等（零新增）。

## 2. 东西落在哪（谁也别去别处找）

```
<ui_shared>/attachments/            目录 0700
├── index.json     0600  文件名/大小/sha256/上传人/时刻/对象关联/可见性/墓碑（**不是账本**）
├── blobs/<sha256>.bin  0600  正文（**内容寻址**：用户给的文件名只进索引、不进路径）
├── journal.jsonl  0600  上传与删除的留痕（append-only；拒绝**不写**）
└── trash/         0700  删除时未被别的条目引用才搬过来的原件
```

上限：**单文件 8 MiB**（`QUOTAGENT_ATTACHMENT_MAX_BYTES` 可覆盖；`/api/attachments/store` 的 `limits` 是可核的真值）、
每对象 32 个、全库 2000 条；类型按**扩展名**白名单（pdf / 图片 / Office / zip / csv / txt / dwg / step …）。
超限、类型不符、空件、文件名含路径一律**有名拒绝**（`413` / `415` / `400`）且**零落盘**。

## 3. 谁看得到（两条判据，别猜）

- **未登录**：读/传/删/列表一律 `401 identity-required`（侧只认会话，查询串改不动"我是谁"）。
- **交付件（`visibility=both`）**：还要**对方是该对象的当事方**（该对象在本侧的事实或交换件里出现过）
  —— 所以"承包商的 RFQ 包附件"供应商能下；**投递给供应商的 PO**（本侧账本里有那条 `po/distributed`）
  供应商也能挂/下（回签件走这条）；**没投递给它的那条 PO**（如持假 id）依然 `403 object-not-in-your-view`。
- **本侧内部件（`visibility=side`）**：只在**上传方本侧**可见（另一侧 `403 cross-side-attachment`）。
- 附件 id 形状 `^att-[0-9a-f]{12}$`：路径穿越、通配、拼接一律 `400 attachment-id-invalid`。

## 4. 导出/打印为什么"与账面一致"

导出内容**不是界面自己拼的**：`report` 贡献只声明"能以哪几种格式导出"，真干活的是**注册者自己的动作**
（`rfq.export` / `po.export` / `po.export-received` / `compare.print`），它的行来自**该插件自己那一侧的账本行**：
- PO（承包商侧 `po.export`）：`po/issued` 的 `lines`（行项目/量/单价/`basis` 单价基准）+ 四段追溯链 + 账本行号；
- PO（**供应商侧 `po.export-received`**）：本侧 `po/distributed` 的 `lines` + 追溯链 + **本侧账本行号**，
  表头另带投递时刻、送货地址/交期与回签状态（"我收到的那份"与承包商那份逐字段同源）；
- RFQ 包：`rfq/published` 的版本事实（`rev` / `quote_by` / `body.hash`）+ 投递件/快照里的行项目（每行带来源）；
- 比价表：`compare/rank-computed` 里**已记录的那次评估**（名次/得分/偏差计数）。

外壳只做**序列化**（CSV / 可打印 HTML + sha256 内容指纹）与上限（5000 行 / 4 MiB，超限如实拒）。

（PO 投递/回签，39 条，截图 `tmp/p8-shots/`）。

## 5. 界面上看不到、"必须回终端才能做"的事（诚实清单）

| 事项 | 现状 | 为什么 |
|---|---|---|
| 供应商给 **PO** 挂件（"回签的 PO"） | **通了**（P8 起）：投递给本侧的那张 PO 就是本侧事实，回签件直接挂在它上面 | 发 PO 时同步投递（两侧各一条 `po/distributed`）⇒ 供应商侧有了这条 PO 的事实；**没投递给本侧的 PO 仍然如实拒**（`object-not-in-your-view`），不给"看不见的对象"挂附件 |
| PO 的**送货地址 / 交期窗口** | 有就给（发 PO 的人填、随投递登记走）；没给就**如实写"对方没给"** | 本侧事实里没有这两个字段时不能编；要补就把它作为**附件**挂在这张 PO 上（回签件/送货单）或走变更单 |
| 附件的**正文级**内容检索 / 在线预览 | 不做 | 正文不进账本、也不进提示词（`docs/design/06-agents-and-prompts.md` §3）；下载即可 |
| 附件进账本 / 进证据包 | **永不** | 见 §10.2 的理由（改事件类型目录、证据包哈希与审计取证语义） |
