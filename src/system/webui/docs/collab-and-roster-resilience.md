## 0. 一句话

协作面（`code/collab.mjs` + `code/collab-ui.mjs`）与名册面（`code/people.mjs` + `code/people-ui.mjs`）读的都是
**人可以手改的 0600 文件**（`<ui_shared>/collab/<侧>.json`、`<ui_shared>/people/roster.json`）。
本页两条纪律：**给人看的字符串过显示层**（`human:limin` → `@limin`；毫秒 ISO → `2026-09-23 08:50（UTC+08:00）`），
**读不懂的形状如实降级**（能读的照读 + 数出来的坏形状 + 该长什么样 + 怎么修）。

## 1. 显示口径（P12 走查实测的自相矛盾，本批修掉）

**症状**（`tmp/p12-shots/t14-*.png`、`t16*`）：同一个对象页上，协作面板写「当前指派 `human:limin`
（`human:wanglei` 指派 @ `2026-09-23T00:48:52.624Z`）」，而「同侧同事（可 @）」写 `@limin（主管 · 在线）`
—— 两种口径并存，用户不知道前者是人名。

**纪律**：

1. **逻辑判据用原始值**：`by`/`to`/`watchers[]`/`reads{}` 仍是 `human:<名字>`（侧与身份只认会话，判据不因显示而变）。
2. **只有给人看的字符串过显示层**：`nameOf()`（去 `human:` 前缀）、`atLabel()`（毫秒 ISO → 本地时刻 + 时区标签）、
   `pretty()`（把**存进文件的事实原文**里的 `human:<名>` 与 ISO 时刻一起洗一遍）。三者都在 `collab.mjs` 里**导出**，
   `collab-ui.mjs`/`people-ui.mjs` 直接 import —— **别各写一份**（重复即漂移）。
3. 覆盖到的位置：对象页协作面板（当前指派 / 交办理由 / 截止）、评论与活动流（谁评论、谁转交、`@` 了谁）、
   工作台「我的 / 我指派的」条目、**通知中心**里协作源那条（标题与正文）、名册面板的「我是谁」。
   事件 `summary`（`human:wanglei 把「…」指派给 human:limin`）是**文件里的事实原文**，显示时洗、文件里不动。
4. 时间**必须写清时区**：`atLabel` 用服务进程的时区并标 `（UTC）` / `（UTC+08:00）`；解析不了的字符串原样显示
   （不替它编一个时刻）。

## 2. 坏形状：**如实降级**（不是异常、不是"空的"）

### 2.1 判据

| 情形 | 结果 |
|---|---|
| 文件里有**整条**读不懂的记录（不是对象） | 跳过 + 计数；写盘时**原样留在文件里**（我们读不出来 ≠ 可以删掉） |
| 字段**容器形状**坏（`watchers` 不是数组、`reads` 不是对象、`assignment` 不是对象/`history` 不是数组） | 该字段跳过 + 计数；`assignment`/`reads`/`events` 在写入时**按新形状重建**（并如实报 `shape_rebuilt`） |
| 数组里的**某一行**形状坏（评论行/活动行不是对象） | 跳过那一行 + 计数（下一次正常保存就不在了，回执里会报） |
| **整份文件**读不出来（JSON 坏了 / 顶层不是对象 / `members` 不是对象） | 面板/通知/状态栏**如实说"读不出来"**（码 + 原因 + 文件 + 怎么修）。**绝不**说成"还没有协作记录 / 名册是空的" |
| 名册的**策略/偏好**（`policy.transfer` / `policy.amount_limit.rules`）读不懂 | 回到**出厂策略**并如实计数；额度规则读不出来 ⇒ 那条动作的额度检查**不生效**（与改前的行为一致，但现在**看得见**）；界面标 `policy_degraded` |

### 2.2 三条实现纪律

1. **只读、不回写**：洗净发生在**读侧**（`load()`），**绝不**为了"修好"而去改人的文件；派生读数
   （`sanitized`/`broken`/`policy_degraded`）**不进文件**（`save()` 里显式剥掉）。
2. **不静默吞掉**：坏形状**逐条计数**（`dropped_total` + 每个字段的 `why`），面板上给两行
   「⚠ 有 N 处坏形状（已跳过，不是"没有"）」+「怎么修」；写入回执里给 `shape_note`。
   **值只放最短的事实**（字段名列表 + "见下方提示"），逐条的「为什么读不出来 / 该长什么样 / 怎么修」
   全部进面板的 `next_action`（提示行会正常换行）—— kv 面板的值列在窄屏上很窄，
   **可读性也是这条要求的一部分**（实测：值放长句时面板看起来像坏掉，放短句 + 提示行才读得下去）。
3. **修好就自动恢复**：`load()` **每次真读盘、不缓存** ⇒ 把文件改对，**下一次渲染/刷新**就恢复（不用重启进程）。
   反向的保护：往**容器形状坏的字段**里追加（关注 `watchers`、评论 `comments`）会被**如实拒绝**
   （`collab-shape-malformed`）并说清怎么修 —— 否则这次写入会在下一次读盘时被跳过（等于白写一次）。

## 3. 工作台卡头计数**按本侧**（P12 §6.1 的登记项，本批在插件层收口）

**症状**：`/app/home/` 的卡片头「有 N 件需要你处理」是**两侧之和** —— 供应商销售 `guqi` 的卡头在
400 包 / 3200 报价的走查里是 **2405 件**，其中 2401 件是**承包商侧**的人工门（`gate.todo` 与 `home.gates`
两块面板读的都是承包商侧事实）。

**纪律**（在外壳改不动的前提下，由**贡献条目的插件**执行）：

1. 条目**属于哪一侧**由贡献它的插件声明（侧标写在标题里：`承包商侧：…` / `供应商侧：…`）。
2. **本侧**（会话侧）的条目按原级别；**对面侧**的条目降级为 `info`（照旧列出来，不藏），
   正文补一句「**不是你要办的**：这一步由<那侧>的人做 —— 卡头「有 N 件需要你处理」只算本侧」。
   `level` 的语义因此收敛为：**`warn`/`bad` = 你现在真能去办的事**；信息、对面侧的活、等待状态都是 `info`。
3. **未登录** ⇒ 没有"本侧"：各面板一律按 `info` 算，由协作面（`collab-ui.mjs`，每张工作台都有）留**一条 `warn`**：
   「未登录：先登录才知道哪些待办属于你」。这不是把计数做小，而是**没登录谁也办不了**（业务动作一律被拒）。
4. 实现：各插件 `code/ui.mjs` 顶上的 `sideScoped(ctx, itemSide, item)`（7 个插件：`system/approval`、
   `domain/{commitments,rfq,quote-prepare,change,clarify,capacity}`）。

**实测**（同一份 400 包 / 3200 报价的沙盘，`tmp/p13-shots/ux/tally-*-{before,after}-fix.txt`）：

| 身份 | 改前「有 N 件」 | 改后 | 说明 |
|---|---|---|---|
| `guqi`（供应商销售） | **2405** | **7** | 2401 件承包商侧的门/待办不再是"要你处理" |
| `wanglei`（承包商采购员） | **2408** | **2404** | 剩下的都是承包商侧自己的（1200 + 1200**同一批门被两块面板各列一次** + 4 条协作） |
| 未登录 | 2405 | **1** | 那一条 = "先登录才知道哪些是你的" |

**已收口（P14）**：`system/approval#gate.todo` 与 `domain/commitments#home.gates` 不再把同一批人工门各列一次
—— 两块面板的条目声明同一个 `dedupe_key`（`gate:<门 id>`），**外壳在开窗口之前按它跨面板合并**（先出现的赢，
级别取更急的一档，`ref`/`action` 缺的补上 ⇒ 合并后仍能点进门的对象页）。实测：承包商侧 `wanglei` 的
「有 N 件」**2404 → 1204**（`tmp/p14-shots/p14-07-workbench-before-2404.png` → `p14-05-...-1204.png`）；
供应商侧 `guqi` 仍是 7。机制见 `notifications-and-dedupe.md` §3。

## 4. 通知中心的**名额上限**：**已收口**（P14）

**修前**：`GET /api/ui/notifications` 只回前 600 条（`NOTIF_CAP`），6328 条产出被截掉 5728 条，顶栏却写
「共 600 条 · 第 1/24 页」—— 数只躲在状态栏「更多」的折叠里，被截掉的**哪儿都点不到**。

**现在**：界面走**通知窗口**（与面板同一套 `w=1` + `pq.notify`）：服务端在**全量条目**上筛选→排序→分页、
只回这一页，并把全集上的数字一并给出 ⇒ 顶栏照实写「共 N 条（后台产出）· 已显示 N 条 · 剩余 M 条」，
与 `/api/ui/status` 的「通知」那一行**同源**，点「末页 ⏭」能一直翻到底（实测第 254/254 页、剩余 0）。
不带 `w` 的旧调用仍是"整份 + 上限 600"（脚本一字不变），但**截断不再静默**（回执带 `dropped`）。

口径、数据属性、前后数字、截图与复跑命令见 `notifications-and-dedupe.md`（本页不再重述，避免漂移）。
