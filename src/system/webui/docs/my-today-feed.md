## 1. 一句话

一个人早上打开界面，**一屏看完今天所有事**：我关注的对象、指派给我/我指派的、我评论过的，
加上**我参的流程**（包 / 报价 / 授标 / 门 / 变更 / PO）上的**本侧账本事实** —— 按时间排成**一条**时间线，
可按类型 / 对象 / 人 / 日期筛，漏看的能**标已读**，每条都能**跳对象页**，能**导出成文本**发同事/写周报。

## 2. 在哪看

| 位置 | 看到什么 |
|---|---|
| **工作台首屏**（`/app/home/`） | 「我的今日：今天的跨对象活动流」——**只讲今天**那一档；这块只作**信息**计入工作台（不改「有 N 件需要你处理」的数量） |
| **本侧视角**（`/app/<侧>/`） | 「我的今日：我参的流程 + 我关注的对象」——**全时间线**（今天 / 近 7 天 / 更早三档） |
| 状态栏 | 协作读数后面跟一段：`今日 N 条（未读 M，跨 K 个对象）` |
| 工具栏（本批动作） | 「标已读：我的今日」·「导出：我的今日（文本/CSV/HTML）」 |
| 视角页「导出 / 打印」区 | `导出 TXT` / `导出 CSV` / `打印 / HTML`（`report` 声明，内容由 `collab.feed-export` 生成） |

**筛选**（都在查询条里，机制见 `scale-and-performance.md`）：筛选片 = **时间档**（今天 / 近 7 天 / 更早）；
按列筛选 = **范围**（我参的 / 本侧，枚举）· **类型**（事实 / 协作，枚举）· **事件类型** · **对象** · **人**（包含）·
**日期区间**；另有按整块的关键字搜索。**筛选只改"看到哪些"**，不改任何事实、不写账本、不动已读水位。

## 3. 口径（每一条都能机读 / 可复跑）

1. **两条来源**：① 同侧**协作事件**（`<ui_shared>/collab/<侧>.json`，0600；指派/转交/关注/评论）；
   ② **本侧账本的事实行**（由外壳 `host.rows(<侧>)` **只读**给进来）。
   `collab.mjs` 自己**不读账本、不 import 任何账本 API**；`collab-ui.mjs` 也只用外壳给的只读行。
2. **「我参的」判据**（不猜）：我关注 / 指派给我 / 我指派的 / 我评论或 @ 过 / 我留下过事件；
   或这一条账本行的 `actor` 就是我。其余算**本侧**（同侧可见，但不冒充"我的"）。
3. **对象与深链**：对象类来自**插件声明**（`surface.objectKindsFor(侧)`）；账本行按它自己声明的 id 键
   （`<对象类>_id` ∪ 该对象类动作里 `from_route` 的字段名）+ `correlation_id`/`ref` 命中已见过的 id 解析。
   解析不出来的行**如实说"没解析出对象"**（只给账本行号，**不编深链**）并在计数里报数。
4. **每条带什么**：时刻（本地时刻 + 时区标签）、类型（事实/协作）、事件（`po/issued`、评论、指派…）、
   对象、人（`@limin` 不是 `human:limin`）、**账本行号**（事实行）、`ref`（对象页深链）、
   未读行额外给「标为已读」（按行预填 kind/id，同一套行内动作机制）。
5. **已读**：与协作面**同一份**每对象水位（`collab.json` 的 `reads[me]`）—— 时刻晚于水位算未读，
   **每人一份**（我标已读不影响同侧别人）。「标已读：我的今日」= 把我参的那些对象一起标到"现在"，
   回执给出标了几个对象、标之前多少条未读。水位比较**按时刻**（账本事实秒精度 / 协作事件毫秒精度混写，
   比字符串会在同一秒里排错 —— 这是本批修掉的真实缺陷，见 `collab.mjs#laterThan`）。
6. **排序**：时间倒序（**按时刻**比较），同一时刻按账本行号/来源稳定 ⇒ 逐条可预期。
7. **导出**：`collab.feed-export`（`format=txt|csv|html`）——内容 = 这条时间线的条目本身
   （事实行带**账本行号**，逐行可对；每条带对象深链）；文本档给出 `digest`（sha256，客户端可自校验）。
   空范围 ⇒ **如实拒**（`feed-nothing-to-export`，不编内容）；上限：单次 ≤ 5000 行 / 4 MiB（外壳序列化口径）。
8. **不进账本**：聚合、标已读、导出都**不写账本**（`ledger_added: 0`）；标已读只写 `<侧>.json` 的 `reads[me]`。
9. **按侧隔离**（结构性，不是过滤）：`feed()` 只读**本侧**账本与本侧协作文件 ⇒ 另一侧的活动、评论、
   内部件正文**根本不在这条时间线上**（负控：`tmp/p24-verify.py` ⑤.6–⑤.8，私域哨兵 0 命中）。
10. **有界**：单次最多 400 条条目（另有服务端窗口分页），账本行扫描 ≤ 20000 行；超出**如实计数**
    （`counts.dropped`），不静默截断。
11. **面板等级**：时间线是**信息**（未读行在本侧视角为 `warn`；工作台那一块一律 `info`），
    它**不冒充待办** —— 工作台「有 N 件需要你处理」只算真待办（人工门/待签/待回）。

## 5. 边界（如实登记）

| 事项 | 现状 | 为什么 |
|---|---|---|
| 门（`approval/*`）事件的对象深链 | 多数能链到**门后面那个对象**（change / award / po / quote，按行里的 id 键解析）；`gate` 对象页本身只在解析得出时才给 | 门的对象类由声明它的插件给（id 键是它自己的事）；**不要**替它猜一个 id 出来（那会给出点不动的假深链） |
| 时间线的"今日" | 服务进程本地日（与同屏的时间标签同一把尺子） | 与协作面的 `atLabel` 同源，避免"标签说是今天、筛选说不算" |
| 工作台「筛选」片上的「全部 N」 | 显示 `0`（外壳 `bucketBar` 对「全部」那颗片的计数硬编码了 `null`） | **外壳既有缺陷**（`code/assets/app.js`，本批不改外壳）：同一行右边的「共 N 行 / 命中 M 行」是真的 |
| 跨侧活动 | **不聚合** | 协作/私域按侧隔离是硬约束（§2/§9）；跨侧只走 QEP 报文与业务动作 |
