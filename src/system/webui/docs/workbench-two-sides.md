# 工作台首屏的"两侧合并"与侧标（谁的队列谁标侧）

<!-- 预算：6 KB。口径真源：`docs/design/29-webui-gui-app.md` §4（双方流程）。本页讲一条纪律与它的来由。 -->

## 0. 一句话

工作台（`/app/home/`）把**两侧**插件贡献的待办并成同一张卡（「你现在该做什么 · 有 N 件需要你处理」），
**外壳不加任何侧前缀**。所以"这条待办属于哪一侧"只能由**贡献这条待办的插件**自己写清楚。

## 1. 为什么必须写（规模下真会咬人）

四个身份、真实规模下的一次走查（400 包 / 1600 报价 / 6324 条通知产出）里：

- 承包商采购员 `wanglei` 的首屏第一行是 —— **「2400 份草稿待你人签提交」**（那是**供应商侧**的 2400 份
  未签草稿）。他既签不了（人签要求署名 = 会话身份，他登录的是承包商侧），也无从判断这是对面的活。
- 同一张卡上，供应商销售 `guqi` 也能看到承包商的待批人工门（那一条**带** `[contractor]` 前缀，
  因为 `system/approval` 自己加了 —— 正好说明"标侧"这条纪律是可行的、只是没被普遍执行）。

## 2. 纪律

1. `view: 'home'` 面板的**每一条**待办标题，写明属于哪一侧：`承包商侧：…` / `供应商侧：…`。
2. 凡"待你签 / 待你回应 / 待你确认"这类**第一人称**措辞，改成**匿名主语 + 侧标**
   （「供应商侧：2400 份草稿待供应商人签提交」），并在正文补一句"这一步由哪一侧的人办"。
3. 数据来源是**本侧**账本（`host.rows('supplier')` / `host.rows('contractor')`）：跨侧读取在这里是
   **故意**的（工作台是合页），但正因为跨侧，标题里更不能省略侧标。
4. 通知中心（`notification-source`）是**外壳聚合面**，插件加不了前缀 —— 那一条仍无侧标，见 §4。

已落实（P12 走查）：`domain/rfq`、`domain/quote-prepare`、`domain/change`、`domain/clarify`、
`domain/capacity`、`domain/commitments`、`domain/compare` 的 `code/ui.mjs` 工作台面板。

## 3. 怎么核对（零终端）

任一侧登录 → 工作台首屏 → 逐条读标题：每条都该带 `承包商侧：` / `供应商侧：`。
截图对照见 `tmp/p12-shots/{t18-supplier-workbench,t19-contractor-workbench-after}.png`。

## 4. 仍做不到（如实登记）

- **通知中心没有侧标**：`notification-source` 的条目由外壳 `notifications()` 汇总（`app-shell.mjs`），
  插件无法在标题里插侧标 ⇒ 承包商侧的人也会在通知里看到"草稿待签署：qd-00042"。要么外壳加侧标，
  要么每个通知源自己把侧标写进 `title`（本批只在工作台面板上做了，通知源的 entry 面太宽，未做）。
- **通知中心的名额上限不在界面上如实说明**（6324 条产出只回 600 条，界面只写"共 600 条"）：要外壳配合，
  已逐条登记在 `src/system/webui/docs/collab-and-roster-resilience.md` §4（含最小改法；那两个文件本轮归
  并发/分页那一批 agent）。
- **同一批人工门被两块面板各列一次**（`system/approval#gate.todo` 与 `domain/commitments#home.gates`）⇒
  本侧计数里有 2× 的重复，属跨插件去重，单独立项。

## 5. 卡头「有 N 件需要你处理」**按本侧**（本批已收口）

口径与实现见 `src/system/webui/docs/collab-and-roster-resilience.md` §3：**本侧**（会话侧）的条目按原级别、
对面侧的条目降级为 `info`（照旧列出、带侧标、说清由哪侧的人办），未登录由协作面留一条"先登录"。
实测（400 包 / 3200 报价沙盘）：`guqi`（供应商）**2405 → 7**、`wanglei`（承包商）2408 → 2404（剩下的都是
本侧自己的）、未登录 2405 → **1**。
