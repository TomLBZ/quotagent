## 0. 一句话口径

> 面板仍给**全量行**（谁的事实谁给，这一层没变）；但**行由服务端按窗口下发**：
> 服务端在**全量行集**上做筛选 → 排序 → 分页，只把**这一页那几行**发给客户端，并把
> **共 N / 命中 M / 第 P/PP 页 / 小计 / 最好的那一行 / 枚举候选 / 命中行键**这些"在全集上算出来的数字"
> 一并给出；客户端**照抄**这些数字与行序 —— 不是"先把全量拿下来再自己截一段"。
> 状态（加载 / 读不到 / 空 / 筛选后 0 行 / 降级）**各自长得不一样、互不冒充**。

## 1. 怎么用（界面上，0 学习成本）

每块 `table` / `files` / `list` / `kv` 面板顶部多了一条**查询条**：

| 控件 | 作用 | 备注 |
|---|---|---|
| **搜这块**（关键字） | 在本块全部行的**所有标量字段**里找（含没显示的列、id、时刻） | 打字即筛（180ms 去抖）→ **服务端按新条件重算并只回这一页**；命中数即时更新 |
| **按列筛选**（可折叠） | 每列一个控件：数值列给**区间**（≥ / ≤）、时间列给**日期区间**、短枚举列给**下拉**、其余列是"包含" | 条件之间是**并且**；与关键字一起生效；下拉候选由服务端在**全集**上算（只有一页时自己算会少选项） |
| **点列头** | 排序：升 → 降 → 不排序（三态，`aria-sort` 同步） | 排序是**稳定全序**：同值按原始行序 ⇒ 与全量排序逐行相同 |
| **翻页 / 每页行数** | 首/上/下/末页 + 跳页 + 每页 10/25/50/100/250/**全部** | 「全部」= **明确选择**全量渲染（服务端就整块回，界面上写着） |
| **计数行** | `共 N 行 · 命中 M 行 · 第 P/PP 页（本页 K 行）· 正在筛选：…` | 数字挂在 `data-count-*`（机器可对账）；服务端窗口下的面板另带 `data-q-server="1"`；取数期间 `data-q-fetching="1"` |
| **清空查询** | 一键清掉关键字 + 列条件 + 排序 | 筛成 0 行时，空态里也有这颗按钮 |
| **已生效的筛选片** | 每个条件一片，点 ✕ 单独摘掉 | 不用回去翻"我到底筛过哪一列" |
| **选中全部命中行**（表有批量动作时） | 跨页选中**全部命中**（不只本页） | 命中行键**按需取回**（默认不下发，点这颗按钮时才为这一块取一次）；换筛选条件自动作废 |

通知中心同一套：**关键字搜索 + 级别/协作标签筛选 + 页码 + 每页条数 + 清空筛选**。

## 2. 请求长什么样（机制；插件仍然什么都不用做）

面板**照旧**只实现 `data(ctx)`（返回 `rows` / `items` / `files` 全量行）。外壳在**路由层**把窗口套上去
（`app-shell.mjs` 的 `parseWindowRequest` / `panelsOf` / `windowPanelData`，`webui.mjs` 的两个路由）：

```
GET /api/ui/panels?view=<视图>&w=1&only=<面板 id>&pq=<JSON {面板 id: {kw, cols, sort, page, size, keys, edits, bucket}}>
GET /api/ui/object?view=<视图>&kind=<对象类>&id=<id>&w=1&pq=…
  · w=1                —— 开窗口（**没有 `w`/`pq`/`only` 就整份下发**：既有工具与脚本行为一字不变）
  · size/page          —— 每页行数（10/25/50/100/250/**0=全部**）与页号（0 基，越界夹回合法页）
  · kw / cols / sort   —— 关键字 / 每列条件 / 排序列（`key:asc|desc`）
  · bucket             —— list 面板的桶筛选片（"我的 / 我指派的 / 全部"）
  · edits              —— 客户端已改的格子（服务端据此把小计算成"你正要提交的那份"）
  · keys=true          —— 要"命中全集的行键"（跨页全选用；默认不要，省几十 KB）
```

响应里每块面板的 `data` 多一个 **`query`**（形状自述在 `/api/ui/surface` 的 `io.window`）：

```jsonc
{"server": true, "field": "rows", "size": 25, "page": 0, "pages": 72, "start": 0, "end": 25,
 "total": 1800, "total_full": 1800, "matched": 1800, "active": false,
 "row_keys": ["…25 个行键…"],            // 行键按**全量行集**算一次 ⇒ 翻页/换筛选不跟着页变
 "matched_keys": [], "matched_keys_on_demand": true, "matched_keys_available": 1800,
 "mins": {}, "totals": [], "group_totals": [], "enum_options": {}, "bucket_counts": {},
 "level_counts": {}, "level_by_bucket": {}, "head": [],   // head/level_counts = 工作台待办用
 "applied": {"kw": "", "cols": {}, "sort": "", "bucket": ""}}
```

为什么**必须**把这些派生物一起给：客户端手里只有一页，`共 N`、小计、`best_when` 的"最小值"、枚举候选、
桶计数、跨页选择的命中行键**都在全集上算**——只给一页而让它自己算，它一定会算错。

## 3. 正确性纪律（性能不得换来错的数字）

1. **窗口里的行 = 全量 → 筛选（关键字 ∧ 每列条件 ∧ 桶）→ 稳定全序排序 → 第 start..end 行**：
   与"不分页时看到的那几行"**逐行相同**（对账脚本按 id 序列逐行比，见 §7）。
2. **计数在全集上算**：`共 N` = 面板给的全部行；`命中 M` = 筛选后剩下的那些；页数与"本页 K 行"只代表窗口，
   不参与计数口径。`data-count-full` 另给一份"面板给的全量行数"供对账。
3. **排序是全序且稳定**（同值按原始行序），所以"排序后第 k 行"与全量排序的第 k 行逐行相同。
4. **筛选可组合且可清空**，只改"看到哪些"，**不改任何事实、不写账本**（§7 的负控用账本 md5 + 待办件目录证明）。
5. **小计 / 组合计 / 最小值 / 枚举候选 / 桶计数按命中行集算**（不是本页）；**编辑跨页不丢**（编辑按「面板|行键」
   存在客户端；改格子后把这一块的 `pq.edits` 送回服务端重算小计，重算前如实标 `data-q-fetching`
   —— 不拿本页的数字冒充全集）。
6. **窗口化渲染**：DOM 里最多只有本页那么多个 `<tr>`；每页行数可选「全部」（明确的全量渲染，会让首屏变慢，界面明说）。
7. **只读**：窗口请求不改账本、不落待办件、不改偏好（§7 负控第 ⑥⑧ 条）。

## 4. 状态：四种样子，互不冒充（不残留旧数据、失败不假装空）

* **加载态**：导航/重载**先把上一页的行清掉**再进入加载（`data-state="loading"` + 骨架）。
* **取新页态**：改筛选/排序/翻页时**这一块**标"正在取这一页…"（`data-q-fetching="1"`），数字仍是上一次的
  —— 不冒充已更新；失败则保留上一页 + 黄条（code + 下一步），**不静默成空**。
* **错误态**：读不到（离线 / 非 2xx / 坏 JSON）渲染**错误态**（`data-state="error"` + `code` + 下一步 +
  「重新读一次」），**绝不显示成"空列表"**。通知读不到时**不清空**通知并**如实标注为陈旧**。
* **空态**：读到了、真的是空的（带 `reason`）。**筛选后 0 行**：`data-state-reason="filtered-out"`，
  与"没有数据"分开，并带「清空查询，看全部 N 行」。降级（`degraded`）另有一态（黄）。

## 5. 通知的名额分配（一条来源不能把通知中心吃光）

通知源由插件提供（`notification-source`）。外壳按来源**轮转取（round-robin）**、总数有上限
（`NOTIF_CAP = 600`），**上限、产出数与每个来源的产出都如实记账**（`/api/ui/surface` 的 `io.notify`）。
本批实测（同一份规模数据、同一次轮询）：修前 200 条**全部**来自 `system/approval`；修后 600 条里 7 个插件都有
（`quote-prepare 231 / commitments 230 / rfq 115 / approval 21 / clarify 1 / capacity 1 / mail 1`）。

## 6. 测量面（怎么量、量什么）

* 服务端（`/api/ui/surface` 的 `io`，只读、只为可对账）：`last_render` 给出**上一次渲染**的
  `spawns / read_spawns / read_cache_hits / ms / panels`，本批新增 **`rows_full`（面板给的全量行）
  / `rows_sent`（真下发的行）/ `windowed_panels`（有几块走服务端窗口）/ `shapes`**；`io.window` 是窗口机制的
  自述（形状、默认每页行数、上限、请求参数、为什么不能只给一页）。
* 客户端（页面里只读的 `window.__Q_GUI_METRICS.last`）：`paint_ms` / `frame_ms`；**`rows_api`（这次真下发的行）
  vs `rows_full_server`（面板给的全量行）vs `rows_dom`（DOM 里真渲染的行）**+ `server_windowed_panels` +
  `paged_panels`；`dom_nodes`；`state`。计数行上的 `data-count-*` / `data-q-server` 也是机器可读的读数。

## 8. 已知限制（如实登记，不假装完成）

1. **服务端仍要把全量行读进来算一遍**（"谁的事实谁给"没变）：省的是**下发字节**与**渲染**，不是服务端的读取量；
   改一次筛选会**重取那一块**（≈80–90 ms，见 §7②），比"整页重载"便宜得多，但不是零成本。
2. **`matched_keys`（命中全集的行键）按需给**：默认不下发（1800 行 ≈ 50 KB）；点「选中全部命中行」时为**这一块**
   取一次。命中超过 **5000** 行时不发并**如实说**（按钮禁用 + 提示先缩小范围），不静默截断。
3. **列条件与页码只在本浏览器**：按身份镜像到服务端的是**关键字 / 排序 / 每页行数**（扁平小值，最多 40 块面板）；
   列条件与页码留在 localStorage（界面提示条里写明）。
4. **附件表的规模由插件自己的上限决定**：`system/attachments` 的 `max_per_object = 32`。
5. **通知总数有上限 600**（防一次轮询拖住页面）：产出多少、截掉多少都记账（§5），但**被截掉的那些不在界面上**。
6. **窗口化渲染 = 分页窗口，不是滚动虚拟化**：滚动条长度不代表总行数（"我在第几页 / 共几页"由计数行给）。
7. **小计的"立刻"变成了"一次往返"**：改格子后行内合计与"已改 N 行"仍然即时；**合计**由服务端在命中集上重算
   （去抖 ~260 ms），期间标"正在取这一页"。这是"客户端只有一页、不许自己算全集"的必然代价。
8. **如实登记的既有现象（非本批引入）**：越侧动作被拒（400 `po-not-derived`）之后，宿主**已经落下的 0600 待办件
   留在原处**（账本零变化）。同一动作在 HEAD 前一份代码上重跑**逐字节同名** ⇒ 与本批无关；口径里的
   "拒绝 ⇒ 待办件零新增"只对**版本冲突**那条路成立（§7④ 的证据文件里带 `pre_existing: true`）。
