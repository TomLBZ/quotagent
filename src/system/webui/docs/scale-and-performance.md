# 规模与长列表（"干一天活的规模也顺"）：机制、口径与实测数字

本页回答三件事：**长列表在规模下怎么用**（查询条 / 分页 / 窗口化渲染）、**机制的口径与声明**
（插件要做什么、外壳做了什么）、以及**可复跑的数字**（首屏耗时 / DOM 节点数 / Python spawn 次数 /
"全量 vs 分页"的对账）。本批（P10）的判据与原始读数见 `tmp/p10-report.md` 与 `tmp/p10-shots/`。

## 0. 一句话口径

> 面板给**全量行**（谁的事实谁给）；外壳在客户端做**筛选 → 排序 → 分页窗口**，
> **计数（共 N / 命中 M）在全集上算**，DOM 里**只渲染当前窗口**那几行；
> 状态（加载 / 读不到 / 空 / 筛选后 0 行 / 降级）**各自长得不一样、互不冒充**。

## 1. 怎么用（界面上，0 学习成本）

每块 `table` / `files` / `list` 面板顶部多了一条**查询条**：

| 控件 | 作用 | 备注 |
|---|---|---|
| **搜这块**（关键字） | 在本块全部行的**所有标量字段**里找（含没显示的列、id、时刻） | 打字即筛（180ms 去抖）；命中数即时更新 |
| **按列筛选**（可折叠） | 每列一个控件：数值列给**区间**（≥ / ≤）、时间列给**日期区间**、短枚举列给**下拉**、其余列是"包含" | 条件之间是**并且**；与关键字一起生效 |
| **点列头** | 排序：升 → 降 → 不排序（三态，`aria-sort` 同步） | 排序是**稳定全序**：同值按原始行序 |
| **翻页 / 每页行数** | 首/上/下/末页 + 跳页 + 每页 10/25/50/100/250/**全部** | 「全部」= **明确选择**全量渲染（界面上写着） |
| **计数行** | `共 N 行 · 命中 M 行 · 第 P/PP 页（本页 K 行）· 正在筛选：…` | 这些数字也挂在 `data-count-*` 上（机器可对账） |
| **清空查询** | 一键清掉关键字 + 列条件 + 排序 | 筛成 0 行时，空态里也有这颗按钮 |
| **已生效的筛选片** | 每个条件一片，点 ✕ 单独摘掉 | 不用回去翻"我到底筛过哪一列" |
| **选中全部命中行**（表有批量动作时） | 跨页选中**全部命中**（不只本页） | 批量动作会把这些行一起发出去；换筛选条件自动作废（比静默发错 id 安全） |

通知中心同一套：**关键字搜索 + 级别/协作标签筛选 + 页码 + 每页条数 + 清空筛选**，
计数行给出 `共 / 命中 / 未读 / 第几页`。

## 2. 插件要做什么（通常什么都不用做）

* **默认可用**：外壳按列的形状自动判筛型 —— `type:'number'` ⇒ 数值区间、`type:'date'|'datetime'`
  ⇒ 日期区间，其余按文本包含。**插件一行不改**，表就有搜索/筛选/排序/分页。
* **想要更准再声明**（可选，`ui-surface.mjs` 的列形状）：给列加 `filter:'enum'|'text'|'number'|'date'`。
  本批给"包 / 报价 / PO / 审批门 / 变更 / 比价 / 产能"这些行数最多的面板补了这类声明
  （金额、数量、交期、时刻、状态、scope 之类；`tmp/p10-column-hints.py` 是那份可复跑的替换清单）。
* 插件**不需要**分页、不需要自己算计数、不需要知道"哪一列是金额"。

## 3. 正确性纪律（性能不得换来错的数字）

1. **计数在全集上算**：`共 N 行` = 面板给的**全部行**，`命中 M 行` = 筛选后剩下的那些；
   两者都在全量行集上算，与"不分页时看到的一样"。本页只代表窗口（`本页 K 行`），不参与计数口径。
2. **排序是全序且稳定**：同值时按原始行序 ⇒ "排序后第 k 行"与全量排序的第 k 行**逐行相同**。
3. **筛选可组合且可清空**，只改"看到哪些"，**不改任何事实、不写账本**、不影响对方视角。
4. **小计按命中行集算**（不是本页）：`data.totals` 的合计在翻页时不会变小；客户端已改的格子优先。
5. **编辑跨页不丢**：编辑按「面板|行键」存在客户端 `state.edits`，行键**按全量行集算一次**
   ⇒ 换页重绘后格子里仍是你改的值，「已改 N 行」累计所有页的改动，「提交编辑」把这些行**一起**发出去。
6. **窗口化渲染**：DOM 里最多只有本页那么多个 `<tr>`；每页行数可选「全部」（明确的全量渲染）。

## 4. 状态：四种样子，互不冒充（不残留旧数据、失败不假装空）

* **加载态**：导航/重载**先把上一页的行清掉**再进入加载（`data-state="loading"` + 骨架），
  屏幕上不会留旧数据；这也在导航过程中给了"正在读"的即时反馈。
* **错误态**：读不到（离线 / 非 2xx / 坏 JSON）渲染**错误态**（`data-state="error"` + `code` + 下一步
  + 「重新读一次」按钮），**绝不显示成"空列表"**。通知读不到时**不清空**通知（清空会让徽标变 0 =
  假装"没有待办"更坏）：保留最后一次成功的那份并**如实标注为陈旧**（提示条 + 通知中心 + 徽标 tooltip）。
* **空态**：读到了、真的是空的（带 `reason` 说明为什么空）。
* **筛选后 0 行**：`data-state="empty" data-state-reason="filtered-out"` —— **与"没有数据"分开**，
  并且带「清空查询，看全部 N 行」按钮。降级（`degraded`）另有一态（黄）。

## 5. 通知的名额分配（一条来源不能把通知中心吃光）

通知源由插件提供（`notification-source`）。外壳的做法（机制，0 业务语义）：

* **按来源轮转取（round-robin）**：每个来源轮流占名额，谁也不会被别的来源整体挤掉；
* **总数有上限**（`NOTIF_CAP = 600`，防止一次轮询把页面拖住），但**上限、产出数与每个来源的产出
  都如实记账**（`/api/ui/surface` 的 `io.notify` + 状态栏「通知」一项）—— 截断不静默；
* 插件自己也要**有界地报**：`system/approval` 的门通知改成"逐条报最急的 20 个 + 一条『另有 N 个门在等』"
  （队列本体在「审批队列」面板里，那里有分页/筛选/逐行动作）。

本批实测（同一份规模数据、同一次轮询）：修前 200 条**全部**来自 `system/approval`（400 个待批门吃光名额，
报价/包/变更/澄清/邮件的通知一条都进不来）；修后 600 条里 7 个插件都有
（`quote-prepare 231 / commitments 230 / rfq 115 / approval 21 / clarify 1 / capacity 1 / mail 1`）。

## 6. 测量面（怎么量、量什么）

机制的读数（都在 `/api/ui/surface` 上，只读、只为可对账）：

| 读数 | 是什么 |
|---|---|
| `io.last_render` | **上一次页面渲染**：`spawns` / `read_spawns` / `read_cache_hits` / `ms` / `panels` |
| `io.notify` | 通知名额：`sources` / `per_source[].produced` / `produced` / `returned` / `cap` |
| `io.python_spawns` 等 | 进程运行期累计（既有） |

浏览器侧的读数（页面里只读的 `window.__Q_GUI_METRICS.last`）：

* `paint_ms`：这次主区渲染**同步**花了多久；`frame_ms`：到**下一帧画完**（含样式/布局/绘制）；
* `rows_api`（面板给的全量行）vs `rows_dom`（DOM 里真渲染的行）+ `paged_panels`（有几块在分页）；
* `dom_nodes`：整页元素数；`state`：`loading` / `ready` / `error`。

## 8. 已知限制（如实登记，不假装完成）

1. **载荷没变小**：面板仍把全量行发给客户端（这是"客户端筛选/排序必须与全量一致"的前提）。
   3.4 MB 的行数据在本地回环上是毫秒级，但在慢链路上仍会拖首屏 —— **服务端分页要改路由与响应形状**
   （`webui.mjs` 的静态路由表），不在本批允许改动的范围内，故如实留在这里。
2. **列条件与页码只在本浏览器**：按身份镜像到服务端的是**关键字 / 排序 / 每页行数**（那三个是扁平小值，
   与既有的 `filters` 有界洗净一致，最多 40 块面板）；列条件与页码留在 localStorage（界面提示条里写明）。
3. **附件表的规模由插件自己的上限决定**：`system/attachments` 的 `max_per_object = 32`（一个对象最多 32 个
   活的附件）——所以单个对象页的附件表最多 32 行（本批实测 32 行 → 2 页），规模压力在"对象数 × 上限"。
4. **通知总数有上限 600**（防一次轮询拖住页面）：产出多少、截掉多少都记账（§5），
   但**被截掉的那些不在界面上**——要看全量得按来源/关键字缩小范围（状态栏给了"产出最多的是谁"）。
5. **窗口化渲染 = 分页窗口，不是滚动虚拟化**：DOM 里只有本页那几行（这就是首屏不卡的原因），
   但滚动条长度不代表总行数；"我在第几页 / 共几页"由计数行给。选「全部」时**就是**全量渲染（会让首屏变慢，界面明说）。
