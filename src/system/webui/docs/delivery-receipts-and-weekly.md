本文讲**怎么用、口径是什么、边界在哪、怎么复跑**。机制真源：`src/system/attachments/code/delivery-receipts.mjs`
（回执存储）+ `src/domain/rfq/tools/weekly-report.py`（只读汇总器）+ 各插件的 `code/ui.mjs`（面板与动作）。

## 1. 两句话

1. **「对方收到了吗？看了吗？」** —— 发包 / 发 PO 之后，**发送侧**一屏看到「投给谁、何时投的（账本事实）」
   与「谁在何时打开过、看过几次（回执）」。回执**不进账本**：它是**读取痕迹**，不是合同事实（理由见 §4）。
2. **「这周到底发生了什么？花了多少钱？」** —— 一张**本周汇报**：发布包数 / 收报价数 / 授标金额 /
   人工门平均等待 / 超时未回；每一项都带**账本行号**，逐行可回账本对；能导出 TXT / CSV / 可打印 HTML。

## 2. 已读回执（投递与已读）

### 2.1 在哪看 / 怎么记

| 谁 | 在哪 | 做什么 |
|---|---|---|
| 供应商（收件方） | 「发给我的 RFQ 包」`quote.package` / 包对象页 `package.mine`；`po.inbox` / PO 对象页 `po.object-received` | **打开就记一条回执**（按会话身份）；面板顶上的说明与对象页上的「已读回执（…方能看到）」那一行，**当次**就告诉你「这一眼已经被记下、对方能看到谁/何时/几次」 |
| 承包商（发送方） | `domain/rfq#rfq.receipts`（包）· `domain/commitments#po.receipts`（采购单） | 一屏看两半边：**投给谁/哪个版本/何时投的**（`rfq/distributed` / `po/distributed`）+ **谁看过/首次/最近/次数**（回执） |

一行的样子（承包商侧）：`包 P26-OPEN-001 · 已投递版本 1 · 投给谁 supplier:g1 · 投递时刻 2026-09-23T05:41Z ·
看过的人 chenmin（supplier侧） · 首次看过 … · 最近看过 … · 看过次数 1 · 状态「已读（1 人看过）」`。

### 2.2 口径（每一条都可复跑）

1. **身份只认会话**：`side` 与人取 `ctx.identity`（`human:<名字>`）。没有会话 ⇒ **不记**（`identity-required`）；
   身份不是收件方那一侧 ⇒ **不记**（回执里没有那个人的名字）。
2. **按对象聚合**（不是流水）：每个对象一个 `readers` 表 —— `{first_at, last_at, count, side, source}`
   ⇒ 天生有界，且「首次 / 最近 / 次数」直接可读。
3. **去抖 60 s**：同一人同一对象在 `DEDUPE_MS`（60 s）内重复查看**不写盘**（回执不该因页面反复渲染而长大）；
   实测三次重复打开 ⇒ 文件**逐字节不变**。
4. **包按「包」聚合、投递按「版本」记账**：看到「已读」**不等于**「看了最新的那一版」——
   要按版本确认请让对方**认收**（`exchange.ack` → `rfq/acknowledged`，那是**账本事实**）。
   **看过 ≠ 回签**：回签（`po/acknowledged`）是对方的人签，有义务语义；已读只是「他打开过这一页」。
5. **有界 + 有名拒绝**：每类对象 ≤ 500 个、每对象 ≤ 64 个读者、文件 ≤ 512 KiB；超限 ⇒ `receipt-limit-reached`
   （**不静默丢**）。坏形状跳过并计数；**整份读不出来时连写都拒绝**（`receipt-store-unreadable`）——
   读不出来 ≠ 可以覆盖掉（与协作面同一纪律），面板上会写「不是还没有人看过」。
6. **不是数据出口**：回执里只有 `对象 id + 人 + 时刻 + 计数 + 从哪看的`。**没有**报价、成本、评分、私域字段；
   实测回执文件里业务字样（`unit_price`/`total_amount`/`quote/submitted`/…）**0 命中**。

### 2.3 界面上怎么点

- 供应商：`/app/supplier/package/<包 id>/`、`/app/supplier/po/<po id>/` —— 打开即留痕（不必额外点任何按钮）。
- 承包商：承包商道「投递与已读回执（对方收到了吗 · 看了吗）」两块面板；行内「打开 →」是该对象的深链。
- 未登录 / 越侧：这两块面板**明确降级**（`identity-required` / `side-mismatch`）且**一行都不给**
  （账本里那半边也不给 —— 周报与回执都是发送侧视图）。

## 3. 本周汇报（只读汇总 · 逐行对账 · 可导出）

### 3.1 在哪看

| 位置 | 看到什么 |
|---|---|
| 承包商道 `rfq.weekly` | 五项指标 + 周窗口 + **事实时刻** + 账本路径 + 附加读数（本周发 PO 张数/金额） |
| 承包商道 `rfq.weekly-lines` | **逐行对账**：每一行 = 一条支撑某个数字的账本事实（`账本行号 / 时刻 / 事件 / 对象 / 金额分 / 口径`） |
| 动作 `rfq.weekly-week` | 「看哪一周」：往前挪 N 周（0 = 本周）。只改**内存便签**，不落盘、不进账本 |
| 「导出 / 打印」区 `report.weekly` | `导出 CSV` · `导出 TXT` · `打印 / HTML`（动作 `rfq.weekly-export`，格式 `csv`/`txt`/`html`） |
| 命令行 | `python3 src/domain/rfq/tools/weekly-report.py --ledger <账本> [--format json|text|csv|evidence-csv] [--as-of ISO] [--weeks-ago N]` |

### 3.2 五项指标的口径（照抄即可对账）

| # | 指标 | 口径 | 证据（`evidence.*`） |
|---|---|---|---|
| ① | 发布包数 | 本周落 `rfq/published` 的**行数**（同一包重复发布 = 多行；另给**去重后**的「不同包 id 个数」`distinct_packages`） | 逐包 `seq / ts / package_id / rev / quote_by` |
| ② | 收报价数 | 本周落 `quote/submitted` 的行数（本侧登记行；另给 `distinct_quotes`）。行数按**行形状**算：多行报价带 `lines[]`，**单行报价没有 `lines[]`** ⇒ 按 1 行（逐行标 `line_shape`） | 逐条 `seq / ts / quote_id / package_id / 行数 / line_shape` |
| ③ | 授标金额 | 本周落 `award/committed` 的逐行 **Σ(量×单价)**，**整数分**：单价优先 `unit_price_cents`，只有 `unit_price` 时 ×100 | 逐行 `seq / award_id / item_id / amount_cents / basis` |
| ④ | 人工门平均等待 | 本周**被决定**的门：`Σ(决定 ts − 请求 ts) / 门数`（秒）。配对键 = **`approval_id` + `scope` + `payload_hash`** | 逐门 `请求行/决定行 / 等待秒 / decision / scope` |
| ⑤ | 超时未回 | `quote_by` < 事实时刻，且本账本里**没有该包的 `quote/submitted`** 的包 | 逐包 `seq / package_id / quote_by / 已超天数` |
| 附 | 本周发 PO | 本周 `po/issued` 行数 + `total_amount`（**账本原生币种**，未换算） | 逐张 `seq / po_id / 行数 / total_amount` |

**为什么门的配对键是三个字段**：本仓实测里 `approval_id` **会被复用**（同一份账本里 `ap-0001` 同时出现在
`award.commit` 与 `po.issue` 两门上）——只按 id 配对会把两个门的等待算到一起。配不上对的决定行进
`gate_unmatched` 并**排除出平均**（不猜、不补）。

### 3.3 三条不许违反的纪律（都在回执与报表里自述）

1. **不取墙钟**：`as_of` 缺省 = 账本里**最大的 `ts`**（已知的最新**事实**时刻）⇒ 同一份账本在任何时间跑
   都输出**逐字节一致**的数字（与 `gate-timeline` 的 `age_clock:"facts-only"` 同一口径）。
2. **不造假数字**：算不出来的行（缺量/缺价、审批配不上对）进 `amount_missing` / `gate_unmatched`，
   **排除出小计**并逐条列出；`人工门平均等待` 在本周没有门被决定时是 **`null`**（不是 `0` —— 0 会被读成「秒批」）。
3. **只读**：汇总器不写账本、不写投影（`ledger_added: 0`）；它只读 `--ledger` 给的那一份。

**实现注记（踩过的坑，别再踩）**：外壳只在面板**没有数据 / 降级**时才渲染 `data.note`；正常态下用户真正
读到的是 `hint`（注册时声明的那句静态文本）与行/条目本身。所以口径与提醒（「已读 ≠ 回签」「不进账本」
「平均等待为『没有』而不是 0 秒」）必须写在 **`hint`** 里（写进 `note` 等于没写）；**当次**读数
（如「已读回执已记下」）要放进 `items` / `facts` / 行里。`hint` 会被 HTML 转义 ⇒ 那里写**纯文本**，
不要写 markdown 的 `**`（用户会看到星号本身）。

### 3.4 导出为什么与屏幕同源

`text` 与 `csv` **就在只读报表的 JSON 里**（由汇总器自己渲染的那一份）。界面导出时直接把这两个字段
交给浏览器（`result.export`），CLI 的 `--format text|csv` 打印的也是同两个字符串 ⇒ **一份口径、两个入口**，
界面侧不再抄一遍，也就不会漂移。HTML 走外壳的序列化（`host.report`），**行仍来自同一份报表**。
三档都带 `digest`（内容 sha256，客户端可当场自校）与逐行 `ledger_refs`。

## 4. 落点与权限（谁也别去别处找）

```
<ui_shared>/receipts/            目录 0700
└── deliveries.json   0600   {objects:{package:{<包id>:{readers:{<human>:{first_at,last_at,count,side,source}}}},po:{…}}}
```

**为什么不进账本**（完整理由在 `delivery-receipts.mjs` 文件头，这里是口径）：账本是**合同事实**的
append-only 链条 —— 进了账本就会进哈希链、进投影、进证据包、进模型输入（AGENTS.md 规则 2）。
「某人某时刻打开过某一页」**不产生任何一方的义务**，把它写进账本会篡改「谁承诺了什么」的语义
（规则 10 的禁区）。所以它与协作面（指派/关注/评论/已读）、名册、附件索引同一口径：
**运营痕迹落 0600 文件，不进账本、不进投影、不进模型输入**。
投递、回签**本身**仍是账本事实（`rfq/distributed` / `po/distributed` / `po/acknowledged`）——
回执只是在它们旁边补一句「看了没有」。

## 6. 边界（如实登记，不假装完成）

| 事项 | 现状 | 为什么 |
|---|---|---|
| 回执的**细化粒度** | 按**包**（不是按版本）聚合 | 收件方打开的是「这个包（最新一版）」这一页；要按版本确认走**认收**（账本事实） |
| 「谁看过」里的**身份** | 只有**会话身份**（`human:<名字>`）与人所在那一侧 | 界面上的读取痕迹只可能知道「这次请求是哪个会话」；IP/设备指纹不进这类文件 |
| 回执的**保留期** | 有界（对象 500 / 读者 64 / 512 KiB），**不做自动清理** | 它是痕迹不是事实：清理由人来决定（删文件即从空开始，账本一个字节不动） |
| 周报的**周界** | ISO 周（周一 00:00:00Z 起、左闭右开），按**事实时刻**所在周 | 「今天/本周」必须与页面上的时刻同一把尺子；读墙钟会让两个人看到两个数 |
| 周报覆盖的**侧** | 只有**承包商侧**账本（发布/收报价/授标/门/超时） | 供应商侧账本的口径不同（它看到的是自己那份）；要供应商视角就显式加一个插件，不要在这里混算 |
| 「上周」对比 | 手工用 `--weeks-ago 1` / 动作「看哪一周」 | 还没做趋势图与环比 —— 不假装有 |

**禁止**：不得把回执写进账本或新增事件类型；不得把回执当数据出口（价格/成本/评分一律不进）；
不得让界面自己算一遍周报（那会出现两个口径）；不得在算不出来时用 0 冒充（必须落到 `amount_missing`
/`gate_unmatched`，或如实说「没有」）。
