# Native email activity digest
<!-- budget: 4096 bytes, hard -->

G9 notification digest (ADR0041): native child `mail-digest` owns account-only, off-by-default delivery preferences. GUI previews the exact recipient and fixed activity summary before manual send. Automatic delivery requires a separate explicit standing permission. SMTP uses the account's configured connection; no raw notification title/body, message, quotation, cost or credentials enter digest content. Bounded batches (1–40), severity threshold, durable delivery keys and throttle prevent empty/repeated automatic mail; ambiguous sends remain uncertain and are not retried. Plugin disposal cancels polling and closes its owned transport. Test: `node src/system/mail/tests/digest.mjs` uses actual loopback IMAP/SMTP, restart, source secrecy and lifecycle checks; `node src/system/mail/tests/product-smoke.mjs` retains inbox/reply/Telegram integration evidence.

Service `ctx.mailDigest.preview/send/history` and GET `/mail-digest`, POST `/mail-digest/send` are owned by the native child. Schema `mail-digest` is account-private; preview fingerprint binds recipient, fixed body, selected IDs/severity and SMTP identity. Successful receipt is durable before rendering; no notification loop is emitted. Operator/user mail credentials stay in the settings credential store. Native polling defaults to30seconds and respects automatic permission, read-only accounts and per-account throttle. Existing private SMTP transport closes on disposal. [Observed G9 evidence](../../../../docs/work/evidence/g9-configuration-and-notifications.md) records native and GUI results and limitations.
