# 并行 subagent 的坑（派单 / 实现 / 机检）

- **多个 child 并行时，tmp 产物必须唯一命名**：两个 subagent 各写 `tmp/t253-run.py`，后者**静默覆盖**前者，
  交付报告里才互相发现。派单时给每个 child 指定**带任务号+角色**的文件名（如 `tmp/t253-exec-run.py` /
  `tmp/t253-qa-run.py`），并在任务里写死"只许写这些文件"。撞名不会报错，只会在复核时让证据对不上。
- **"实现 + 机检"并行派单前，必须先把接口契约写死**：类名、方法签名、异常类名、返回字典的键名，
  在**两份**任务书里逐字相同地给出。否则两个 child 各自发明形状，父方要花一轮做接口对齐。
  契约里还要写明"哪些文件不许改"（两个 child 都必须把注册表/文档留给父方）。
- **`qa.registry.register()` 同一 AC 重复注册会直接抛 `RuntimeError`**：一条 AC 只能挂一个函数。
  所以"给已有 AC 补充断言"的正确做法是**新建 AC** 并在文档里写明两个 AC 的分工
  （例：`AC-AUDIT-003` = 计划侧、`AC-AUDIT-005` = 执行侧，合起来覆盖同一条 FR），
  而不是试图往原 AC 上追加。
- **破坏性代码的门必须自带变异自证**：让子代理交付"能删文件/能改状态"的实现时，要求它在机检里附
  **≥3 处单点变异**（关掉根路径校验、关掉审批校验、关掉幂等短路…），并给出每处变红的原始输出。
  本轮 5/5 处变异全红，才敢相信那 22 条断言不是橡皮图章。
- **子代理的"我没验证的东西"清单要读**：它比"我通过了什么"更有信息量（例：并发、崩溃窗口、
  权限拒绝分支只有代码没有实测）。这些条目要原样进 Evidence 与决策记录，不要替它圆场。
- **一次性脚本里别写成 `x = x + f"""…""", encoding='utf-8'`**：那是赋值不是写回，Python 只在遇到结尾的 `, encoding=...` 时才报 `unmatched ')'`；同一轮里我犯过两次。写盘一律 `p.write_text(x + f"""…""")`，并且跑完必须核对文件字节数变化。
- **门与提交必须 `&&` 串联；不要写成两行**：把校验放一行、`git commit` 放另一行，红的门照样会被提交（本项目已踩两次：一次是自进化产出轮，一次是 FAQ 契约轮）。固定写法：`tools/verify.sh <门> && git add -A && git commit -F - <<'MSG' …`，提交被拒比提交错误便宜得多。
