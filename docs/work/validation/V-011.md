# V-011 · 邮件/文件投递在双方间实际可用

<!-- budget: 16 KB。结论状态见 register.json；结论由人签，agent 只备料与登记 -->

## 假设与判定

- **假设**（`functional-requirements.md` §1）：邮件/文件投递在双方间实际可用
- **验证方式**：与一家供应商做一次真实投递演练
- **判定标准**：成功送达并可校验签名则成立
- **影响**：决定 P1 绑定选择
- **判定态**：`pass` / `fail` / `partial`（部分成立时写 `partial` 并在结论里注明范围）

## 需要谁

- 1 家供应商的对接人（15 分钟，只需收一个文件并回一个文件）+ 承包商 IT 1 人

## 准备的材料（已备好，可直接用）

- `templates/v011-delivery-drill.md`（演练步骤与校验清单）
- 演练用合成 QEP 报文：`tools/run.sh -m quotagent.qa suite s1` 后从 `services/scenarios.py` 的投递路径可复现，或用本文档『备料自检』里的命令生成

## 怎么做（步骤）

1. 先按『备料自检』在本地跑一遍（合成密钥 + 本地目录投递），确认脚本与校验步骤可用。
2. 把生成的 `.qep.json` 报文通过**真实渠道**（邮件附件 + 共享目录）发给供应商对接人。
3. 请对方：保存文件、回一个『已收到 + 文件哈希（sha256）』的邮件，不要打开我们的系统。
4. 比对：对方回报的哈希与我们发出的哈希一致 → 完整性可校验；再确认对方能否用我们给的一行命令复验签名。
5. 存证据 `docs/work/evidence/EV-<编号>-V-011-<渠道>-<YYYYMMDD>.txt`（含两次哈希与对方回信原文）。
