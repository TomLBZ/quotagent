## 假设与判定

- **假设**（`functional-requirements.md` §1）：采购方接受『AI 排序建议 + 人工签署』
- **验证方式**：与 2 名采购负责人评审 S1 比价结果
- **判定标准**：≥ 1 名愿意在真实包上试用则成立
- **影响**：决定 `ctx.compare` 的推广路径
- **判定态**：`pass` / `fail` / `partial`（部分成立时写 `partial` 并在结论里注明范围）

## 需要谁

- 2 名采购负责人（各 45 分钟）；需要能看到 S1 的比价输出（可屏幕共享）

## 准备的材料（已备好，可直接用）

- `templates/v003-review-form.md`（评审表）
- S1 比价结果：`tools/run.sh -m quotagent.qa suite s1` 的 `facts.ranking` + `docs/work/metrics-baseline.md`

## 怎么做（步骤）

1. 先在本地跑 `tools/run.sh -m quotagent.qa suite s1`，把 `facts.ranking` 与各报价的 TCO 分量表（从 AC-COMPARE-002 的输出可复现）导出成一张对照表给评审人看。
2. 评审时说明两条硬规则：排序建议**只是建议**、最终数字与授标**必须人签**（规则 3 / INV-005）。
3. 记录评审人对三件事的态度：是否愿意用、愿意用到哪一步（只看建议 / 采纳排序 / 在真实包试用）、最不放心什么。
4. 存证据 `docs/work/evidence/EV-<编号>-V-003-<姓名或代号>-<YYYYMMDD>.txt`。
