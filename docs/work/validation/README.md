## 这里有什么

| 路径 | 内容 |
|---|---|
| `V-001.md` .. `V-012.md` | 每条假设的**执行包**：需要谁 / 准备的材料 / 怎么做 / 产出与例子 / 放回哪里 |
| `register.json` | **登记表**（机器可读）：状态、结果、结论、签字人、证据路径 |
| `templates/` | 可直接发出/打印的材料（访谈表、盲测说明、报价表单、数据采集表、咨询清单、演练清单） |
| `examples/` | 填好的样子（合成数据，仅供对照） |
| `../../tools/v-kit.sh` | 把某条 V 的材料打包到 `tmp/v-kit/V-00X/`，交给现场的人直接用 |
| `../../tools/check-v-register.py` | 登记表校验器（`tools/verify.sh v`） |

## 接手指令（人做，30 秒看懂）

```sh
cd <仓库根>
tools/verify.sh v                      # 看当前状态：12 条都在，全部 open（待人工）
tools/v-kit.sh V-002                   # 打包某条 V 的材料 → tmp/v-kit/V-002/
tools/v-kit.sh --all                   # 打包全部 12 条
```

1. **领材料**：跑 `tools/v-kit.sh <V-ID>`，把 `tmp/v-kit/<V-ID>/` 里的东西发给现场的人
   （每个执行包第一段写清了"需要谁、多长时间"）。
2. **做验证**：按执行包里的"怎么做"逐条执行；模板就是记录表，**原话照抄，不要替我方总结成"接受/不接受"**。
3. **放回结果**：把原始产出存成 `docs/work/evidence/EV-<编号>-V-00X-<来源>-<YYYYMMDD>.txt`（表格/问答/回信原文）；
   然后编辑 `register.json` 里那一条：填 `status`、`results`、`conclusion`、`decided_by`（必须 `human:姓名`）、
   `decided_at`、`evidence`。字段形状照 `V-00X.md` 的"例子"小节抄。
4. **校验**：`tools/verify.sh v` → `RESULT: PASS` 才算登记合法（缺证据、缺签字、留空都会红）。
5. **入库**：一轮一批 `git add -A && git commit -m "docs(validation): V-00X 结论（<来源>）" && git push`。
6. **收尾**：12 条都有结论后，把 `docs/work/progress-checklist.md` 的 `T-117` 标 `done`（evidence 列填
   `register.json` + 相关 `EV-<编号>-V-00X-*`），并按 `roadmap.md` §2 的门 G0 由人签署。

## 判定态约定

- `open`：待人工（默认，12 条现在都是这个）——**不得**出现 `conclusion`。
- `pass` / `fail` / `partial`：已有人签字；必须有 `conclusion` + `decided_by=human:*` + `decided_at` + 证据文件。
  部分成立写 `partial` 并在 `conclusion` 里写明成立的范围（例："2/3 家接受，但都要求能导入"）。
