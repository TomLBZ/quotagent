## Reproduction and ownership

Launch `EVIDENCE_DIR=tmp/agent-experience/g9-fixture node src/system/mail/tests/product-fixture-server.mjs`; it prints loopback ports and writes `connection.json`. Optional pagination setup: `node src/system/notifications/tests/browser-fixture.mjs` writes62 clearly synthetic local notices to the isolated `tmp/agent-experience/g9-browser-data` directory before host startup. The browser requires this pagination fixture; it does not claim those notices are real procurement events.

Build the above assets, then start the existing host with `QUOTAGENT_WEBUI_PORT=8650`, `QUOTAGENT_PRODUCT_DATA=tmp/agent-experience/g9-browser-data`, `QUOTAGENT_WEBUI_ASSETS=tmp/agent-experience/g9-assets`, and the fixture Telegram API base. Browser scripts default to `http://127.0.0.1:8650/quotagent/`; `BASE_URL`, `FIXTURE_FILE`, `EVIDENCE_DIR` override them. All browser configuration/business writes use visible controls; direct browser HTTP reads only corroborate UI results. Use a fresh isolated dataset for the complete journey: the final step intentionally marks the pagination notices read and mutes their sources.

Settings owns `code/service.mjs` transaction/scopes, generic routes, schema field/provenance modal and YAML workbench. Domain providers authorize their own workspace/project/section references; procurement integration has independent worker evidence. `origins` allows an owner to label environment/file base values without exporting secret values. `QUOTAGENT_SETTINGS_INIT` selects an operator bundle with format `quotagent/settings/v1`, an `ownerId` and schema patches; startup status is visible in configuration history. No host changes are required.

Notifications own complete `window` filtering/counts, serialized distinct-source merge, source-level readback/mute preferences and explicit mark-matched. Mail owns the disposable `mail-digest` child, separate transport, account preferences, preview and delivery history. Existing mail/Telegram notices now declare explicit plugin attribution. The digest selection honors alert source/severity preferences, preserves maximum batch count, and never forwards arbitrary notification bodies/titles, quotes, costs or messages. Every selected notification ID/severity and SMTP result is an account-ledger fact. Digest receipts do not create new notifications and cannot self-trigger a mail loop.

## Limits

SMTP acceptance is not final mailbox delivery. Ambiguous delivery stays uncertain and is not automatically replayed. Digests deliberately contain counts rather than sensitive source text. Configuration rollback uses private journals and compensating ledger facts; it is local-process persistence, not a distributed transaction. Reversible plugin activation hooks cannot undo arbitrary outbound commitments. Filesystem rename/private modes and actual local protocol behavior were observed; provider OAuth authorization/token refresh remain outside this change. Live public usability/reasoning evaluation belongs to the root release check.
