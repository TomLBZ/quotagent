## 三、覆盖的判据 → 断言（逐条对应门里的行）

| 契约条款 | 门里的断言 |
|---|---|
| up 幂等启动 / 不重建不覆盖数据 | R4（真起 + 健康 200 + URL 可达）、R6（二次 up：`state=already-up`、pid 不变） |
| status 一行 JSON（`{ok,service,pid,port,url,healthy,ready_ms,degraded[]}`） | R5（一行 + 字段齐 + degraded 项带 reason/next_action）、R7（两次 status **逐字节一致**） |
| down 回收本次启动的进程、不删数据 | R8（`stopped/released` + 端口真释放）、R8b（重复 down 幂等） |
| doctor 只读、逐项 next_action、退出码 0 = 能跑 | R1（7 项 + 逐项 next_action + 退出码 0）、R1b（只报指纹，不回显内容） |
| 外部凭据不阻塞启动 | R2（空配置 + 无 token 下 doctor 仍 0）、R9（凭据缺失下 up **仍成功** + status 报 `available:false`） |
| 端口被占必须报出来 | R3（别的进程占端口 ⇒ doctor 非 0 + next_action）、R10（up 非 0 + 日志路径） |
| —— | R11（`run` 的 **4 处单点变异全红**，每处先在未变异基线上确认"不红"；产品树字节不变） |
