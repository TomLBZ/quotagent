一、改了什么：让"归档"成为契约的一部分（语义不变或加强，无一处放宽）
  1) tools/check-docs.py
     - AC 的"定义文件"从**单个文件**改为**集合**：docs/work/acceptance-criteria.md
       + 同目录 glob `acceptance-criteria-archive*.md`。口径写在脚本头 + 两个常量 AC_MAIN / AC_ARCHIVE_GLOB，
       实现是 ac_definition_files()（主文件恒在首位，其后是所有匹配的归档）。
     - **ID 完整性语义不变**（每个引用 ID 必须存在于集合内），只是查找范围扩大。
     - **FR↔AC 覆盖（无孤儿）同步扩到集合**：搬进归档的 AC 行与它还在主文件时受**同一个**断言约束
       （不扩这一处就等于给归档开豁免，故必须扩）。
     - **新硬断言**：归档必须真被读到 —— 任一归档文件 0 条 AC 定义行即判 FAIL；
       输出里可见 `archives=[<文件>:<AC 行数>, ...]`（可观察证据，不是空集合比对式的静默通过）。
     - 预算规则不变：`docs/work/*.md` 32 KB，归档与新文件同样受检。
  2) tools/check-ac-registry.py
     - 同一集合（主文件 + 归档）判「**phase 恰为 P0** 的 AC 必须已在 `qa list` 注册」→ P0 行搬进归档后
       不变量保持（负控 2a 证明：P0 行搬进归档仍绿；2b 证明：从归档拿掉那条 P0 行立刻红）。
     - 新增两道守卫（只加强）：归档 0 条 AC 行 = FAIL；集合里 0 条 P0 = FAIL（拒绝假绿灯）。
     - 输出里同样可见 archives=[...]。
  3) docs/design/12-documentation-standard.md §2：AC 定义处一行写明"主文件 + 同目录归档 = 门的 AC 定义集合；
     归档不豁免任何断言"，避免"一处一事实"出现文档与现实漂移。
