一、选型：**(a) 收窄扫描范围**；不选 (b)「保留范围 + 读不到就跳过」
==========================================================================================
量出来的事实（先量后断）：
  · 旧口径 `md_files()` = `ROOT.rglob("*.md")` 只排 `.git` ⇒ 静默期自报「扫描 267 个 markdown 文件」，
    其中 **166 个在 tmp/**、3 个在 host/node_modules/（= 169 个临时/派生）。
  · 新口径 = 契约文档 **98** 个（267 − 169），排除的 169 个全是临时/派生目录下的 .md。
  · 引用数从 **6128 → 2798**（tmp 里整树副本的重复引用不再计入），0 未解析；预算仍 **98 个文件受检**
    （预算表的 pattern 本来就匹配不到 tmp/）；FR↔AC 覆盖不变（147 条 FR 均关联 AC、126 条 AC 无孤儿）；
    `[ok]` 行一条不少（AC 定义集合 / ID 完整性 / 占位符 / 预算 / 覆盖）。
三条理由（写进了 tools/check-docs.py 的模块 docstring 与 decisions.md D-072）：
  1. 临时副本**不是契约文档**：AC-RUNTIME-001 自己的「干净副本」口径（checks_runtime.py 的 IGNORE_DIRS =
     {.git,.venv,tmp,__pycache__,node_modules,…}）本来就排除它们 ⇒ 门的判据范围应当与之一致。
     旧口径把副本当判据 = 判据范围大于「本用例的影响面」（D-071 第 3 条）。
  2. 「读不到就跳过」会让门**依赖别人的写入节律**（谁在写、写多快都改绿红），并且它把「临时副本消失」与
     「真契约文档被删」混为一谈 —— 后者必须红；跳过就是把缺陷当通过（= 放宽）。
  3. 跳过也治不了**半拷文件**：副本写到一半时读到的是截断内容（引用数/预算偏小），那是比崩溃更隐的假绿。
边界（不放宽）：契约文档在读窗口里消失**仍然判红**（见 §三）。断言语义只改「范围」这一条口径，
且改后**更精确**（契约文档一个不少 + 门自报数对账），不是把断言变松。
