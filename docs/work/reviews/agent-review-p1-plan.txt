### 0.3 未落库编号的处理（有实测证据的硬约束）

门的 ID 完整性检查要求每个 `前缀-NNN` 引用都在定义文件中存在。实测：把一个尚未落库的 ADR 编号与一个
尚未落库的证据编号写进 `tmp/` 下的 .md，`tools/verify.sh docs` 立刻 `FAIL`（ID 完整性）。因此本文件：

1. 宿主层 ADR 编号（ADR-0012）曾经不可引用：它落库前，`host/README.md` 的引用让门变红（宿主批次以自己的提交补上定义行后恢复绿）。本文件现已直接引用它；这条规则对**每个**尚未落库的编号继续生效；
2. 不写出 P1 的**新证据编号**，一律写作 `EV-<NNN>`（宿主批次已占用 EV-038，P1 从其之后连续分配）；
3. 不写出**新增 AC 行/任务行**的编号，一律写作"新增一条 AC（编号在 B1 落库后引用）"。

**规则**：任何"先写计划、后落 ID"的动作都必须在同一批里补齐定义行；门红不提交。

## 1. P1 的 MVP 完成定义（DoD）

### 1.1 一句话

**两个真人、两台机器（或两个容器）、两条命令各自起一侧进程，走完"发布 → 澄清广播 → 升版 → 报价 →
比价与 Flag → 授标 → 变更 → 审计包独立验证"一轮；全程任一承诺动作在任一侧都无法绕过人工门，
私域字段在对方三处（投影 / 模型输入 / 视图）都不可见，全过程可离线重放、可被第三方独立验证。**

"最小"的边界：不做 UI（命令行为界面）、不做邮件/ERP、不做谈判、不做自进化（roadmap §3 "明确不做"）。

### 1.2 演示环境（G1 的最低配置）

| 项 | 取值 |
|---|---|
| 两侧进程 | `contractor-ops`（承包商）与 `supplier-bid`（供应商）各一个进程，两个账本目录（`QUOTAGENT_ROOT` + `QUOTAGENT_TMP` 各指独立目录） |
| 投递 | 共享目录（最低门槛）；relay profile 可选；两者语义相同（ADR-0006） |
| 第三方 | 一台只读机器：`tools/verify-pack.sh` 独立验证审计包 |
| 离线 | 全程无网（NFR-REL-005 / `10` §9）；宿主层依赖一次安装后不再联网 |
| 时长 | 30–40 分钟（含对抗性演示），支持中途停机后从交接三件套恢复 |

### 1.3 演示剧幕（用户视角的端到端，8 幕）

| 幕 | 谁做 | 命令（示例） | 观众看到什么 | 由谁保证 |
|---|---|---|---|---|

| 4 报价 | 供应商（成本模型私域 + 人工批准数字） | `qa quote submit` | 成本构成只在本侧可见；agent 定价只是建议，人改数字后批准；无批准记录则提交抛错 | AC-TRUST-001 / AC-PRICE-001 / AC-APPROVE-002 |

| 7 变更 | 供应商提 → 采购批 | `qa change propose|approve` | 变更必须引用原报价条目与单价基准；差额可复算；未批准的变更不影响任何金额 | AC-CHANGE-001 / AC-CHANGE-002 |

### 2.1 各批明细

`tools/run.sh -m quotagent.qa ac <AC> --evidence EV-<NNN>` → 全量回归 → 更新三处状态 →
`tools/verify.sh docs && git add -A && git commit … && git push` → `git ls-remote origin` 回读。
回归命令统一为 `tools/verify.sh docs && tools/run.sh -m quotagent.qa suite s1..s4`（B15 之前场景集仍是
单进程语义，作为回归基线；重放一律在新账本上跑，避免幂等去重把"重放"变成"重复投递"）。

## 5. 风险登记册

### 5.1 双运行时（Python 内核 + cordis 宿主）——把系统切成两个运行时的头号风险

| ID | 风险 | 影响 | 对策 | 触发信号 |
|---|---|---|---|---|
| R-P1-01 | 语义双实现漂移（事件五模式 / effect 回收 / 配置否决在两侧各有一套，行为不一致；已知第一处差异是 `waterfall` 传值语义：cordis 用可变载荷且 `next()` 无参，P0 Python 版 `next(work)`） | 同一断言在两侧结论不同，门失去意义 | 组合与生命周期**只**由宿主（cordis）实现，Python 侧不再扩展 plugin/events（ADR-0002 内核冻结）；差异按 ADR-0012 第 2 条钉进 `host/smoke.mjs` 与桥接 AC；对照测试：同一夹具两侧结论必须一致；冲突以账本事实为准并另写 ADR（ADR-0012 Revisit #3），不得改 AC | 对照结论分歧；`tools/verify.sh cordis` 与桥接 AC 不能同时绿 |
| R-P1-02 | 账本双写（宿主侧直接写账本文件） | 哈希链/审计证据失效，账实不符 | 桥接协议只接受"意图/命令"，账本写入只发生在 Python 侧；桥接 AC 含负控（注入写请求必须被拒且留痕） | 宿主进程打开 ledger 文件 |
| R-P1-03 | RC 依赖（cordis 预发布版本）API 变更 | 宿主层随时可能崩，回归不稳 | `host/package.json` 钉确切版本 + lock 入库；升级单独 commit 且先跑冒烟；无网可跑 | `tools/verify.sh cordis` 偶发失败 |

### 5.2 双进程 / 双账本分离

| ID | 风险 | 影响 | 对策 | 触发信号 |
|---|---|---|---|---|
| R-P1-08 | split-brain：同一字段双方各写各的 | 两份账本永久分歧，恢复不可能 | 字段权威方矩阵 + `sync/conflict`；承诺字段一律 `pending_human` 且双方各自一条人工记录才算成立（ADR-0003） | 同一条目两侧值不同且无 `sync/*` 事件 |
| R-P1-09 | 幂等/序号失效（重发造成第二条事实，或越过 `seq` 空洞推进） | 事实重复或错序，审计重建失败 | `(msg_id)` 与 `(correlation_id, type, body_hash)` 双去重 + 空洞不跳号（FR-QEP-003）；回归 AC-QEP-002；重放必须在新账本 | 同一 `msg_id` 出现两条事实 |
| R-P1-10 | 时钟不可信（两台机器时间偏差） | 顺序判断错误 | 定序只用 `seq` + `prev_hash`；`sent_at` 仅用于展示与重发窗口；超窗请求重发而非静默 | 两侧 `seq` 顺序与时间顺序矛盾 |
| R-P1-11 | 私域跨进程泄露（成本明细/标底经出站报文或共享目录泄露） | 违反 AGENTS.md 规则 4，P1 失去意义 | 三处过滤点（投影/模型输入/视图）+ 负控（把私域字段塞进出站必须被拒）；relay 不解析 body（AC-INTEG-002） | 对方侧出现私域字段 |
| R-P1-12 | 人工门被另一侧绕过（伪造对方批准） | 承诺可被伪造，治理失效 | 承诺冲突需双方各自一条 `human:*` 记录；AC-APPROVE-001/002 在双侧各跑；无自动批准（AC-APPROVE-003） | 单侧记录即可推进承诺 |
| R-P1-13 | 并发写冲突（两个 agent 同时改同一批文件；宿主批次已改 `tools/verify.sh`、`12` §1，并已提交 ADR-0012 与 EV-038） | 门红、提交互相覆盖 | 写冲突面同一时刻只允许一批持有（§3）；门绿才提交（`tools/verify.sh docs && git add…` 串联短路）；未落库编号不在任何 .md 写出（**实测发生过**：宿主 ADR 落库前 `host/README.md` 的引用让门红，随后由宿主批次自己的提交恢复绿） | `tools/verify.sh docs` FAIL 且失败项指向他人文件 |
| R-P1-14 | 崩溃恢复不可靠（一侧在报文半途崩溃） | 事实丢失或重复 | 账本重放 + `inbox/` 补入 + 未同步事件重发（同一 `msg_id`）；NFR-REL-001/002 的检验放在 B15/B16 | 重启后状态与重放结果不一致 |
| R-P1-15 | 共享目录语义差异（网络盘 rename 不原子、半写被读到） | 解析半截报文 | 临时文件 + rename（AC-INTEG-001 回归）+ 半写不读；relay 不可达时排队退避；手册写明支持的目录类型 | 出现解析失败的报文 |
| R-P1-16 | 两台机器部署差异（解释器/路径/权限） | 现场演不动 | `tools/bootstrap.sh` 幂等；`QUOTAGENT_ROOT`/`QUOTAGENT_TMP` 覆盖；手册的 5 条命令必须在干净机器照抄可跑 | 目标机器上 `tools/verify.sh smoke` 非绿 |

**绝不许假（任何情况下都不得降级或伪造）**

1. 人工批准记录（不得代签、不得自动批准、不得"临时旁路"）；
2. 私域边界（三处过滤 + 负控；不得用"删掉一切都看不见"蒙过）；
3. 账本哈希链与审计包**独立**验证（篡改必须失败）；
4. 归一化的拒绝语义（不得加兜底默认值、"先算出来再说"）；
5. 重放确定性（同输入同输出；必须在新账本上跑）；
6. `seq` 空洞的挂起语义（不得跳号推进）；
7. 反例集只增不减（不得删改旧用例；新增需人批）；
8. **两个真进程**（不得用"同进程里两个对象"冒充双侧演示）；
9. 现场结论与门签署（V 项、G1 只能由人签字；agent 不得预填）；
10. EV 证据的**原始输出**（不得用人工摘要替代命令输出；每份含时间/命令/commit/退出码）。
