# 领域痛点分析：承包商 ↔ 供应商的采购与报价闭环

<!-- budget: 24 KB. 标注约定: [假设]=待现场验证; [常识]=行业通行做法, 来自公开资料与从业常识 -->

## 0. 方法论与免责

本文是**结构化假设集**，不是已核实事实。凡未经客户现场验证的判断一律标 `[假设]`，并在
P0 阶段列为待验证项（验证清单见 `../work/functional-requirements.md` §1 的 V-001..V-012）。设计文档只依赖以下三类：
(a) 结构性事实（谁在什么时点掌握什么信息，(b) 可机检的一致性要求（单位/税率/币种/版本），
(c) 由 (a)(b) 直接导出的自动化机会。**痛点强度排序需现场校准，不在此断言。**

## 1. 链路重建（承包商视角）

```
需求/设计 ──▶ 采购包划分 ──▶ RFQ(询价) ──▶ 澄清问答 ──▶ 报价接收 ──▶ 比价/技术评审
   │             │              │            │            │             │
   └─ 规格/图纸  └─ 包边界/接口  └─ 截止时间  └─ 口径修正   └─ 结构化     └─ 谈判/授标
                                                        │
                    订单(PO) ◀── 授标(Award) ◀──────────┘
                        │
        变更单(Change Order) ──▶ 交付/验收 ──▶ 结算对账(发票核对)
```

### 1.1 采购包划分（Work/Bid Package）

- 现状：工程师按专业/区域/供应商能力手工切包；包边界写在图纸说明、接口矩阵与邮件里。
- 痛点：**包边界与接口责任在纸面上，不在数据里**；两包之间的"谁负责"是后期争议与变更的第一来源。
- 可自动化：把包定义成"范围 + 接口 + 计量规则 + 交付物"的结构化实体，边界即数据，
  跨包接口自动做覆盖检查（有接口但无归属即报错）。
- 强制人工点：包的商业合理性（是否值得拆、是否要捆绑）保留人裁决。
- `[假设]` 实际项目中包边界常在一轮澄清后修改，因此包定义必须版本化，而非一次冻结。

### 1.2 RFQ 生成与分发

- 现状：Excel 工程量清单 + PDF 图纸 + Word 条款，用邮件或供应商门户分发。
- 痛点：**口径不可比**——同一份清单，甲供应商按"综合单价"，乙供应商按"人材机分列"，
  丙供应商漏项后写"含在总价内"；单位/税率/币种/含税口径各不相同，比价前必须人工重算。
- 可自动化：清单模板化 + 计量规则显式 + 单位/币种/税口径强制字段；分发即版本发布。
- 强制人工点：清单本身的技术正确性（工程量算错不是 agent 能负责的事）。
- `[假设]` 多数承包商已有清单模板，缺的是**机器可读的模板 + 版本绑定**，而非重写模板体系。

### 1.3 澄清问答（Clarification / RFI）

- 现状：邮件 + 电话 + 会议纪要；答案有时只发给提问方，其他投标人不知情。
- 痛点三重：(a) **不对称**——澄清答案未广播给所有投标人，导致公平性与合规风险；
  (b) **版本错配**——投标人基于 RFQ v1 报价，授标时已到 v3，产生结构性偏差；
  (c) **重复轮次**——同类问题反复问，知识不沉淀。
- 可自动化：结构化澄清工单（问题绑定到 RFQ 版本与条目 id）、答案强制广播、FAQ 知识沉淀、
  超时提醒与新版本通知。
- 强制人工点：答案内容（技术/商务口径的最终解释权）。
- `[假设]` 澄清轮次是报价周期中最耗时的环节之一；其可压缩空间来自"答案复用 + 广播自动化"，
  而非让模型替人作答。

### 1.4 报价接收与可比性

- 现状：报价以 Excel/PDF 提交，商务人员手工抄录进对比表。
- 痛点：**抄录误差**与**口径漂移**；偏差表（deviation）/除外责任散落正文，比价时被忽略；
  报价有效期、付款条件、质保期等非价格条款不被量化，导致"最低价中标、履约最亏"。
- 可自动化：结构化解包（报价 ← 报价模板契约）、偏差项抽取与归一、TCO（总拥有成本）折算：
  价格 + 交期成本（进度款/工期影响）+ 付款条件资金成本 + 质保风险 + 偏差代价。
- 强制人工点：TCO 权重由公司策略决定，不是模型决定；异常低价是否接受必须人批准。
- `[假设]` 供应商愿意提交结构化报价的前提是**承包商侧先给结构化询价**（本文的对称性假设）。

### 1.5 比价、谈判与授标

- 现状：人工对比 + 会议决策；评分表常与最终决策脱节。
- 痛点：**评分不可复现**、决策依据不留痕、谈判让步无记录、授标后"当初为什么选它"说不清。
- 可自动化：评分模型显式化并可重放（给定同样的输入得到同样的排序）、让步与承诺全程入账、
  授标建议附带引用链（每条结论指向账本条目）。
- 强制人工点：**授标决策与价格承诺只能人签**（AGENTS.md 规则 3）。
- `[假设]` 采购方对"AI 建议排序"的接受度低于"AI 做归一化与风险提示"；后者先行。

### 1.6 变更与结算

- 现状：变更靠邮件与现场签证，结算时逐条回忆。
- 痛点：变更链断裂、单价基准漂移、发票与订单/验收三方核对靠人。
- 可自动化：变更单引用原报价条目与单价基准，自动重算差额；三方核对（订单-验收-发票）
  做成一致性检查。
- `[假设]` 变更争议的根因是"原报价没有条目化的单价"，所以条目化报价同时解决 1.4 与 1.6。

## 2. 供应商视角

| 环节 | 现状 | 痛点 | 自动化机会 | 强制人工点 |
|---|---|---|---|---|
| 读包 | 人工读图纸/清单 | 漏项、误读规格、工时估错 | 抽取清单条目、规格与偏离点提示 | 工程量最终确认 |
| 成本构成 | 经验 + 历史表 | 成本不可沉淀、报价无依据 | 成本模型（材料/人工/机具/管理/风险/税）条目化 | 成本基价与利润策略 |
| 报价策略 | 拍脑袋加利润 | 中标率与毛利无反馈闭环 | 历史中标/失标数据回流为策略记忆 | 最终报价数字 |
| 交期承诺 | 口头 + 经验 | 产能冲突、交期不可信 | 产能日历 + 关键路径校验 | 交期承诺 |
| 澄清 | 邮件问 | 答案只到自己手上、来回慢 | 工单化 + 知识库 | 提问措辞（避免暴露策略） |
| 中标后 | 重新填表 | 数据重复录入 | 报价 → 订单 → 交付 一次录入多处复用 | 合同条款确认 |

`[假设]` 供应商侧最痛的**不是算价**，而是"读包 + 澄清 + 重复录入"三件事占用的人力。

## 3. 双方对接的结构性痛点（本系统的设计靶心）

1. **口径漂移（Semantic Drift）**：同一字段两端含义不同（含税/不含税、单位、计量规则、
   币种锁定日）。→ 对策：字段级语义契约 + 归一化流水线 + 不一致即拒绝（fail loud）。
2. **非结构化交换**：Excel/PDF/邮件是载体，不是接口。→ 对策：QEP 报文 + 报价必须结构化解包。
3. **版本错配**：报价基于旧版 RFQ，招标方已修订。→ 对策：报价报文强制携带 `rfq_rev`，
   比价前做版本一致性门；不一致即进入"重新报价或作废"分支。
4. **澄清不对称**：答案未广播导致公平性风险。→ 对策：答案强制广播至全部在册投标人，
   广播本身是账本事实。
5. **双方同时改同一字段**：两端各有本地版本，同步时冲突。→ 对策：**字段权威方**规则
   （工程量归承包商、成本构成归供应商、交期归供应商、条款归承包商）+ 三方协调 + 冲突上报。
6. **数据主权顾虑**：供应商不愿交出成本构成，承包商不愿泄露标底。→ 对策：隔离 realm +
   只交换报价与必要证据；模型上下文永不包含对方内部数据。
7. **承诺的不可逆性**：AI 不得替人提交报价或授标。→ 对策：Fact / Intent / Commitment 三分类，
   承诺必须人工批准（ADR-0004）。
8. **审计与合规**：招投标要求可追溯、可复现、留存证据。→ 对策：追加式账本 + 模型可见即已记录 +
   证据包导出。
9. **对抗性输入**：报价正文可能含诱导性文字（prompt injection）、异常低价、虚假产能承诺。→
   对策：内容与数据分离（正文永不直接进模型决策路径）、护栏事件、必要时人工复核。

## 4. 可测指标（用于 P1/P2 验收，不做事前承诺）

| 指标 | 定义 | 用途 |
|---|---|---|
| 报价可比率 | 无需人工重算即可进入比价的报价占比 | AC-COMPARE-002 |
| 澄清轮次 | 同一 RFQ 版本的平均澄清往返次数 | AC-CLARIFY-003 |
| 口径一致率 | 两端字段语义校验通过率 | AC-NORM-001 |
| 比价耗时 | 从末份报价到生成可评审比较表的时间 | AC-COMPARE-004 |
| 变更可追溯率 | 变更单能自动关联到原报价条目的比例 | AC-CHANGE-002 |
| 审计重建率 | 抽样会话可从账本完整重建模型输入的比例 | AC-AUDIT-001 |
| 人工介入率 | 每份报价需人工编辑的字段占比 | AC-EVOLVE-002 |

**上述指标不设实现前目标值**：任何目标值都必须先由 P0 mock 采集基线，再由人类设定。

## 5. 明确不解决的问题（范围边界）

- 不做工程量自动计算与图纸识别的**最终正确性**担保（模型产出均为建议，人签）。
- 不做供应商准入/征信/合规资质的司法判定。
- 不做电子招投标平台的法定程序替代（本系统是协作与一致性层，不是法定招标平台）。
- 不在本阶段做支付、发票开具、税务申报。
