# ADR-0003 跨方账本同步：字段权威方 + 三方协调

Status: accepted

## Problem

双方各自持有账本并在本地修改同一实体。Cordis 的 `reconcile()`（`include/src/journal.ts:195-242`）
给出了三方协调的正确骨架（base / theirs / journal，逐键判定 + 冲突上报 + 合并折叠），
但它的冲突策略是"**文件赢**"——因为那是单进程内的配置文件，存在唯一权威副本。

跨组织不存在这样的副本：两端都在写，谁都不该无条件赢。若采用"先到先得"或"时间戳赢"，
会产生两个后果：数据主权被破坏（改对方有解释权的字段），以及承诺字段被静默覆盖（法律风险）。

## Decision

保留三方协调的算法骨架，替换冲突策略：

1. **字段权威方矩阵**（`03-exchange-protocol.md` §4.3）为每个字段族指定权威方：
   包范围/清单/条款归承包商；单价/偏差/交期/成本构成归供应商；澄清问题归提问方、答案归发包方；
   审批记录各自本方且不可代签。
2. **非权威方的修改不外发**，降级为建议（`intent/suggestion`）供对方采纳——需求"我想改"与
   约束"我不该改"同时成立。
3. **冲突上报**产出 `sync/conflict` 事件，含双方值、基线值与所用规则；自动解决也留痕。
4. **承诺类字段冲突不自动合并**：状态挂起，要求双方各自留一次人工裁决记录，缺一不可。
5. `base` 用 revision 向量表达（每个实体的版本号），随每次同步推进。

## Consequences

**正向**

- 冲突有确定赢家与确定留痕，可复核、可解释（P7）。
- 数据主权在协议层被表达，而不是靠"大家都别乱改"的约定。
- 与 Cordis 的协调骨架兼容，实现可直接照搬其 diff/merge/上报结构。

**负向**

- 权威方矩阵需要按行业与合同逐项确认，配置负担高于"文件赢"。
- 承诺字段挂起会阻塞流程，需要明确的人工裁决 SLA（否则成为流程瓶颈）。
- 矩阵未覆盖的新字段必须先定义权威方才能启用，扩展成本被前置。

## Alternatives rejected

| 方案 | 否决理由 |
|---|---|
| 文件赢 / 先到先得 | 破坏主权，且承诺可能被静默覆盖 |
| 时间戳赢（LWW） | 时钟不可信；且"后改者赢"等于奖励越权 |
| 强制单一中心权威库 | 与"双方各自持有账本、可离线推进"（NFR-REL-005）冲突 |
| 禁止双方修改同一实体 | 现实中必然发生（澄清后价格变、范围变），只是把冲突藏起来 |

## Revisit conditions

1. 若现场验证表明某类项目的协作实际上是"承包商单方主导、供应商只读"，可简化为单侧权威。
2. 若承诺字段的人工裁决成为高频瓶颈（超过约定比例），重新评估矩阵粒度或引入第三方仲裁。
