# ADR-0002 内核冻结 + 能力以接缝三角扩展

Status: accepted

## Problem

自进化系统最危险的失败模式是"agent 修改了它的信任根"，此后一切证据链、审计结论与
版本兼容性都失去意义。需要一个明确、可机检、且不依赖 agent 自觉的边界。

## Decision

1. **冻结面**：`kernel/*` 命名空间——账本、事件分发、插件装载、QEP 信封校验、
   人工门的存在性、密钥与信任配置。agent 对这些内容的任何写入请求一律拒绝（INV-010）。
2. **开放面**：提示词片段、策略参数（区间内）、归一化规则、护栏规则、新 Provider、评测用例
   （只增）。见 `07-self-evolution.md` §2 的可写面清单。
3. **能力一律按接缝三角提供**：Service Definition（接口与不变量）+ Provider（实现）+
   Consumer（使用面，通常是模型可见工具）。三者缺一不构成接缝。
4. **配置分层**：行业模板 → 公司策略 → 项目 → 标段 → 会话覆盖；越具体者优先。
   跨方冲突不适用本条（见 ADR-0003）。

## Consequences

**正向**

- 自进化的爆炸半径被限定在开放面，内核的稳定性不依赖 agent 的判断力。
- 替换一个 Provider 即可整体改变行为（例如定价策略、计量规则库），无需分叉代码。
- 三角齐全的检查能防止"偷偷把政策写进工具实现"这类隐性耦合。

**负向**

- 某些紧急修复可能需要走 ADR 流程，无法由 agent 当场完成（这是有意设计）。
- 内核与外围的边界需要持续维护；边界模糊时会出现"业务逻辑渗入内核"的诱因。

## Alternatives rejected

| 方案 | 否决理由 |
|---|---|
| 允许 agent 改内核但要求人工复核 diff | 复核无法保证语义安全（形式化保证不存在），且举证责任倒置 |
| 用权限系统（RBAC）控制 | 权限只能限制入口，不能表达"卸载后无残留"这类语义约束 |
| 不设内核，全部可改 | 等于放弃审计与兼容性，与 P4/NFR-COMPAT 冲突 |

## Revisit conditions

1. 若出现必须频繁修改内核的真实需求（频率 > 每季度一次），说明内核边界划错，需重新划分。
2. 若引入形式化检查（例如可机检的 effect 覆盖证明），可适度放宽开放面。
