# ADR-0004 事实/意图/承诺三分，承诺必须人工批准

Status: accepted

## Problem

Cordis 的时间可组合性建立在"副作用可完全回退"上（`fiber.ts:277-340`）。但采购报价场景里
有一类动作**根本不可回退**：已提交给对手方的报价、已签署的授标、已发出的订单。
Cordis 的语义在这里给不出答案——不能撤回一个已发出的承诺，只能事后更正。

若不对此建模，会出现两类事故：
(a) agent 的"建议"被当作承诺发出（模型幻觉直接进入合同关系）；
(b) 系统试图"回滚"一个已经对外生效的动作，产生账实不符。

## Decision

在所有实体、协议报文与 UI 上采用三分：

| 类别 | 可变性 | 产生者 | 可否回退 | 协议字段 |
|---|---|---|---|---|
| **Fact** | 不可变，只追加 | 任意一方记录已发生的事 | 不需要（已发生） | `class: fact` |
| **Intent** | 可变、可撤回 | 单方（agent 或人） | 可撤回 | `class: intent` |
| **Commitment** | 不可变，只能追加更正 | **双方 + 人工批准** | 不可回退，只能更正 | `class: commitment` |

判据（一句）：**该对象是否让一方对另一方产生可主张的义务。**

配套硬规则：

1. 承诺类报文缺 `approvals`（且批准者必须是人）一律**拒收**（INV-005）。
2. 承诺类字段的跨方冲突不自动合并，转人工裁决（ADR-0003）。
3. 不可回退动作的"撤销"表达为**追加更正条目**（`quote/revised`、`change/approved`），
   旧条目永久保留（审计要求）。
4. agent 只能产生 Fact 与 Intent；Commitment 只能由人签署后由系统落账。

## Consequences

**正向**

- 模型幻觉与商业承诺之间有一道结构性隔离，而不是靠提示词约束。
- 审计可回答"这一步是谁批的、依据是什么"，因为批准记录本身是账本事件。
- 回退语义边界清晰：本地状态可卸载回收，对外承诺只能更正——与物理世界一致。

**负向**

- 人工门是流程瓶颈，必须设计为不阻塞异步队列（`06` §6）。
- 更正链条会随时间变长，需要投影层提供"当前有效承诺"的聚合视图。
- 三分类需要在数据模型、协议、UI 三处保持一致，跨层遗漏会造成语义漏洞。

## Alternatives rejected

| 方案 | 否决理由 |
|---|---|
| 全部动作都可回退（忽略物理约束） | 与事实不符，会造成账实不符与合规风险 |
| 全部动作都需要人工批准 | 退化为人工系统，自动化价值丧失 |
| 用"agent 置信度 + 阈值"自动放行承诺 | 置信度不可校准，且责任无法落到人 |
| 只在 UI 层做人门（后端可绕过） | 安全边界必须在唯一对外出口上（`06` §2.3 规则 3） |

## Revisit conditions

1. 若法规或行业惯例允许某些低额承诺自动生效（例如小额备件采购），可将该类动作单列一等，
   但仍需保留人工可撤销窗口与留痕。
2. 若实践表明人工门延迟使流程不可接受，优先改流程与批处理策略（批量批准），
   而不是取消人工门。
