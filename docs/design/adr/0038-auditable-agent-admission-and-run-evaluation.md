# ADR-0038 Auditable agent admission, context and run evaluation
<!-- budget: 8192 bytes, hard -->
Status: accepted for implementation

## Problem and preserved contracts

The product provider records inputs/outputs and token usage, and native conversation/workroom controls preserve completed work across pause, stop and restart. It does not yet admit against explicit budgets, bound concurrent provider requests, distinguish circuit/backpressure causes, or explain omitted context. Historical runtime middleware and S1–S4 evaluations have useful requirements but are not wired into the native product. Sources: `product-ai.mjs`, `product-usage.mjs`, `conversations.mjs`, agent-workflows `engine.mjs`, and G6 in the requirement audit.

The pinned party workspace introduced by commit `871ee88` remains authoritative for all model/tool work and resumptions. Human approval of external commitments, account memory review, ledger/QEP semantics and existing native control transitions remain unchanged. A missing measurement is never a zero or a successful business outcome.

## Decision

1. Provider controls are a native child of the existing agent-runtime provider and expose `aiRuntime`. Every real HTTP attempt passes through this service. It owns disposable concurrency/queue/circuit state and schemas; meaningful admission/reservation/outcome receipts use the existing append-only store. Bounded diagnostic subscriptions/rings and read-only projections do not create a second authoritative ledger or write merely because someone opens a dashboard.
2. Account settings declare token/window/run budgets, output caps, bounded retry and context limits. Administrator capacity settings bound total concurrent and queued calls. Budget defaults preserve usable existing behavior. Users can inspect limits and change their own settings through native configuration UI. Reservations occur before dispatch and are released/reconciled after observed outcomes. Interrupted/unknown charges remain conservatively reserved until their window expires; no restart resets known spend.
3. Monetary values are integer micro-units of an explicit currency. Pricing is an explicit human-supplied provider/model tariff with source/effective date, captured with each estimate. Actual reported input/output/cache usage is distinguished from conservative byte-based preflight reservations (not a universal tokenizer bound). Unknown pricing or usage remains unknown; a configured money limit cannot silently treat it as free. Account rate estimates are not provider invoices. A single request larger than a whole budget explains that waiting cannot help; a depleted rolling window gives a meaningful retry time.
4. Circuit state tracks consecutive transport/provider failures by account and connection. A threshold opens the circuit; cooldown permits a bounded half-open probe, whose actual result closes or reopens it. Admission returns stable reason codes and next actions. Monotonic, injectable time governs in-process duration/window/cooldown decisions; durable timestamps allow conservative reconstruction. Queue timeout is an explicit error. Pause/stop/unload aborts queue waits, sleeps and requests.
5. Automatic retry is bounded and limited to explicitly eligible HTTP responses such as temporary 429/503, respecting `Retry-After` within configured waiting limits. Timeout, cancellation, network ambiguity, invalid credentials and malformed success are not silently retried. Attempt count and final result remain visible. Provider-side idempotency is not assumed: an explicit account-scoped request identity joins in-flight calls or replays a durable completed result/failure; conflicting payloads are rejected, and interrupted ambiguous requests cannot automatically dispatch again.
6. A shared context assembler bounds source groups, memory, history, per-item bytes and final payload bytes. It preserves complete tool-call/result groups and human instructions. Omission receipts report original/included counts, bytes, identifiers/hashes, reasons and next actions; omitted facts are not fabricated summaries. Genuine empty data is distinct from unavailable assembly. Selected context is ledger-recorded before the provider call. Conversation/workroom UI exposes the latest receipt and relevant degradation notice.
7. Runtime views join real admission, provider, context and run records without exposing prompts, credentials or other accounts' private content. Users see own activity; administrator aggregate views are metadata only. Existing token charts remain valid and add explicit priced/unknown coverage, failure/queue/circuit counts, bounded realm timelines and measured durations. State is observational; viewing it cannot retry a provider or change a business record.
8. Native evaluation uses frozen references to actual recorded model/run inputs and outputs, human-specified assertions, and append-only counterexamples whose activation requires human review. Replaying a recorded artifact deterministically reruns assertions without a model or business mutation; a fresh live-provider attempt is separately named and cannot be represented as deterministic replay. Baselines count observed statuses, tool/source events, cycle times and human interventions, showing unknown/uninstrumented metrics explicitly. S1–S4 historical synthetic scenarios remain labelled synthetic evidence and do not stand in for live product success. Business supplier statistics stay owned by commercial-workbench.

Additive receipt families: `agent/admission-*`, `agent/provider-*`, `agent/context-*`, `agent/evaluation-*`. Existing `agent/model-*` retains its input/output/usage meanings. Terminal model usage extends with request/run references, attempts, explicit pricing snapshot and typed stop reason. New collections are projections over the same ledger; no kernel or QEP semantic change.

## Acceptance and limits

Loopback protocol fixtures first: budget refusal/window reset, unknown price, integer rounding, queue/circuit/probe, eligible bounded retries, timeout/cancel, idempotent result/failure/conflict, restart reservations, disposal and metadata privacy. Native conversation/workroom tests must retain pinned workspace after account navigation switches. GUI must configure controls, inspect context/cost/reasons, run recorded evaluation and approve a retained counterexample without scripts.

This does not promise lower quotation cycle time, perfect prompt-injection detection, monetary savings or deterministic fresh model responses. Those require recorded outcomes and appropriately scoped measurements. Invalid or missing rates are an explicit configuration problem, not a reason to fetch an undocumented price or invent a bill.

## Sources

Current transport documentation supports configurable output limits and response usage: [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/). Temporary rate limiting may supply Retry-After, with bounded backoff recommended: [OpenAI rate-limit guide](https://developers.openai.com/api/docs/guides/rate-limits). These sources inform transport handling only; no current tariff is hardcoded.

Alternatives rejected: unlimited implicit retry; counting missing usage as zero; deleting difficult counterexamples; billing estimates without rate provenance; silently slicing whole contexts; replaying external actions during evaluation; reviving old SSR/CLI management carriers.
