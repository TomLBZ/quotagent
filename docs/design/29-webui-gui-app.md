## 0. 用户原话（规则真源，逐字保留）

> "Webui不是什么账本投影或者只读路由，而是**完整的 gui app**。他虽然不包含业务逻辑，但是必须允许插件
> 通过**注册自身的 UI 元素、交互方式、业务逻辑等**，从而允许实现任意的功能。你可以参考 deepseek harness
> 的 gui 做的事情，也可以类比 **vscode 的 gui** 所做的事情。我也明确说过你**可以用前端框架**。但现在你写的
> webui 还只是一个简陋的像说明书一样的只有查询功能的垃圾，完全不满足我提出的**双方必须能够通过 gui 完成
> 全部的业务流程**这个要求。"
> （另两条原话见归档 §0。）

## 1. 定义（唯一口径）

- **WebUI = 双方的完整 GUI 应用**：像 VS Code 那样**可长期使用的应用外壳**（多视图/导航/命令面板/通知/快捷键/状态栏 + 深链），像 DeepSeek harness 的 GUI 那样**用界面驱动真实流程**；它自己**不含业务语义**，但必须让**插件把自己的一切搬上界面**。
- **零业务语义 ≠ 零功能**：外壳给机制（布局与槽位、命令与动作、表单与校验、通知与确认、导航与深链、状态与续跑、
  键盘与可访问性），**功能由插件注册进来**。
- **判定标准（这才是"完成"）**：双方**仅通过 GUI**走完全部业务流程（§4）——不打开终端、不手敲 `tools/verify.sh`；每个动作**真落到账本/待办件**；人工门**可点、可等、可催、可签**（清单见 §4）。
- **允许前端框架**：任何前端框架/构建产物都行；不因"零内联脚本"这类旧判据拒绝交互能力（安全判据 = 脚本只来自
  受信来源 + 插件注册面）。

## 2. 明确禁止（旧口径，一律删除，不得保留副本）

1. 禁止把 WebUI 描述成"账本投影装配"、"只读路由"、"只提供注册面（不含功能）"、"三块第一屏 + 0 JS"。
2. 禁止用"页面结构锚点 / 快照 hash / 0 内联脚本"这类**没有交互**的判据冒充 UI 验收。
3. 禁止新增任何**只冻结旧形态**的测试与门（UI 快照门、seed 门、ui-mutate 变异门）：判据与本文冲突 ⇒ **删除**（引用链一并改干净）。
4. 禁止用"门禁全绿"当作进度汇报：**推进业务功能是唯一重要的事**；门只是安全带，不是目的。

**已删的东西逐条登记在 §21**（旧只读页 / 旧 UI 形态判据 / 旧运维面）；它们**不得复活**。

## 3. 架构（机制在外壳，功能在插件）

- **外壳（`src/system/webui/code/`）**：应用壳（多视图/导航/命令面板/通知/快捷键/状态栏/深链）+ **注册面**与装配器
  （0 插件 id、0 业务名词）+ 把"界面事件 → 动作"接起来的**动作总线**。
- **注册面（插件往上挂的，至少这几类**；语义不许缩水）：① **视图/面板/区块**（placement、顺序、可见性条件）；
  ② **交互方式**（字段与校验、表格编辑与批量、拖拽、右键菜单、快捷键）；③ **动作/命令**（`id` + 标题 + 入参 schema + 权限 + 确认策略 + 真调哪个后端动作）；④ **业务逻辑钩子**（动作的**服务端一半** + 返回增量：结果、待办件、要刷新的视图）；⑤ **通知与状态**（进度、失败原因、next_action、待门队列）。
- **写路径不可绕过**：GUI 动作只"发起"，对外承诺类动作仍必须经人工门与既有唯一写者（`tools/*-apply.py` 之类）落账本；
  GUI **不是**第二条事实写路径。
- **可撤销**：一切注册返回 disposer；插件卸载后其视图/动作/快捷键**全部消失**（AGENTS.md 规则 1）。

## 4. 双方完整业务流程（UI 必须覆盖，逐条可点）

- **承包商（业主侧）**：发 RFQ（行项目/币种/截止）→ 看谁收到、谁没回、还差多久 → 催报与答疑 → 收报价 → 比价排序（权重可调、贡献可解释）→ 人工门：**批准/驳回/要变更** → 授标承诺（人签）→ 发 PO（逐行可追溯）→
  变更与价格让步（需批准）→ 审计与证据包（导出、验证）。
- **供应商（投标侧）**：看自己的 RFQ 包（只出自己那份）→ 提问/澄清 → 备报价（草稿可续）→ 提交报价（人工门：签名）→
  谈判 → 承诺交期（产能日历、冲突提醒）→ 中标/落标通知与 PO 确认。
- **共同侧**：审批队列（等多久、卡在谁、可催办/升级/终止、**可批准/驳回**）、授权区间（谁能批多少、越界一键升级）、截止看板、邮件通道状态、用户空间插件。
- **每一步都要能"在 APP 内闭环"**（含写操作）；失败时给**可复制的下一步**。

## 5. 落地路线（按用户优先级：先能用，再完善）

1. **P0**：应用壳 + 注册面 + **一条真实闭环**（备报价→签名提交 / 发 RFQ→批准→授标），真起服务、真点、真回读账本。
2. **P1**：剩余双方流程逐条搬进 GUI；**P2**：可用性打磨（键盘/命令面板/深链/空态与错误态/可访问性/布局持久化）。
3. **验收**用真实用户视角（subagent 扮两端走一遍）；见归档 §5。

## 7. 台账与持久化（口径以本节为准）

1. **`/api/routes` 的 `auth` 是真实值**：业务路由（`${prefix}/<侧>/…`）**按路径推导**为 `identity-session`（与 `code/identity.mjs#gateBusinessRoute` 同一判据）；`none` 只给真公开入口；表里给 `auth_basis`，**别手抄**（抄的会漂）。**同一份判据也钉在外壳与数据面上**（P50）：`/app/<侧>/**` 与 `/api/ui/panels|object` 的 `view` 越侧一律 403 `side-mismatch`；无会话则清单照旧、**行不下发**（真源 `side-scoped-shell-data.md`）。
2. **偏好/已读/布局/筛选整份在服务端**（按身份，见 §9），**不是账本事实**。
3. **邮件通道有界面入口**：工作台面板 + 界内表单（POST `${prefix}/mail/config/`）→ `identity-mail-apply.py` → 唯一落盘者 `config-apply.py` 写 YAML（凭据永不回显；**`/workspace/config.yaml` 只读**）。
4. **人签动作的服务端身份门**：`permission: 'human-signature'` 的动作上**服务端**校验「已登录 + `signature` == 会话身份」（401 `identity-required` / 403 `signer-mismatch`，账本零新增）；界面**不代签、不写账本**（批量见 §19）。
5. **一份报价 = 一次人签**：整表**一次提交** ⇒ **一条**草稿（逐行 `lines[]`），人签**一签提交整份**；单行报价 body **逐字节不变**（12 键）；缺行/改行**有名拒绝**（`pending-tampered`/`line-item-not-found`/`draft-tampered`）。

**禁止**：界面不得成为第二条事实写路径；不得手抄 `auth`；不得把偏好类文件当账本事实。**真源**：`src/system/webui/docs/identity-and-selfservice.md`、`docs/design/19-mail-contract.md`；**完整口径（0600/有界/拒绝码）见归档 §7**。

## 8. 名册与角色：「同事」= **名册里的人**（不是「登录过的人」），角色**限动作**而非限视图

1. **名册是权威取值处**：`<ui_shared>/people/roster.json`（0700/**0600**、原子写、有界、超限**如实拒**），按**侧**分片（`side` 只由会话给）；**不进账本**（是**可改的运营配置**，不是合同事实）。
2. **`@提及`/指派/转交都从名册取值**（候选与校验同源 `GET /api/people/suggest`）：未知名字 ⇒ `unknown-colleague`（列本侧名册）；跨侧 ⇒ `cross-side-mentioned`；**登录即登记**（第一次登录即进名册、角色「待指派」＝有名字没权限）。
3. **按角色限动作**（服务端判据，**在任何执行之前**；拒绝 ⇒ **账本与待办件零新增**）：转交别人的活 ⇒ `transfer-not-yours`；额度超我角色 ⇒ `role-limit-exceeded`（给出金额/额度/**该找哪个角色**）；有管理员之后改人/改角色/改策略**只有管理员**（`admin-required`）。
4. **角色不改变签署权**（结构性）：额度/角色判据跑在「署名 == 会话身份」**之后**、插件自己的服务端一半**之前** —— 它**只能否决、不能放开**（§7.4 一字未动）。

**禁止**：不得把名册/角色/额度写进账本或当模型可见输入；角色只能收紧不能放开动作。**真源**：`src/system/webui/docs/people-and-roles.md`；复跑 `python3 tmp/p5-people-verify.py`；**逐条规则（限额单位/转交角色/bootstrap）见归档 §8**。

## 9. 通知偏好 / 已读 / **布局** / 筛选：**整份**服务端化（按身份）

**判据**：`GET|POST ${prefix}/api/ui/notif-state`（`POST` 整体替换）把已读集合、静音插件、最低级别、**面板布局**、筛选片全部落 `<ui_shared>/webui/notif-state.json`（0700/0600、原子写、有界、洗净；坏形状**如实计数**）；**按会话身份隔离**（换浏览器/换设备读回同一份；未登录 ⇒ 401 `identity-required`）；**只读路由的方法围栏**：非 GET ⇒ **405 + `method-not-allowed` + `Allow: GET`**，且**先按方法判据拒绝、再做身份校验**。**真源**：`src/system/webui/docs/people-and-roles.md`、`collab-and-roster-resilience.md` §4；口径见归档 §9。

## 10. 文件交换与可打印文档（对象级附件 / 导出 / 打印）

**能力**：对象级附件（`files` 声明）+ 可导出/可打印文档（`report` 声明 + 打印/下载）。
**判据**（**10.1** 附件声明 · **10.2** 不进账本 · **10.3** 下载校验 · **10.4** 路由经注册面 · **10.5** 导出/打印；逐条矩阵见归档 §10）：`url` **只允许本服务相对路径**（外站丢并计数 `absolute-url-refused`）；上传走**原始字节**、**侧与署名只认会话**；下载**按侧 + 身份**（交付件且是当事方 / 内部件只在**上传方本侧**，否则 `403 cross-side-attachment`）；**附件不进账本**（`ledger_added` 恒 `0`）；路由**经注册面**（**只读路径各带 POST 孪生路由 405 + `Allow: GET`**）；导出/打印 = **声明由插件给、内容由插件生成**（超限 5000 行 / 4 MiB **如实拒**，行带 `ledger_seq` 锚）。
**禁止**：不得把界面引去第三方取/传文件；不得用宿主那个 16 KiB 读体夹取（**静默截断**）；外壳不得生成/改写内容。
**真源**：`src/system/webui/docs/files-and-exports.md`；**形状/矩阵/路由清单 = 归档 §10**；复跑 `python3 tmp/p6-verify.py`。

## 14. 乐观并发（**不后写覆盖前写**）/ 分享 / 导出列可配

**能力**：三件（对象并发 / 分享 / 导出列可配）都在外壳层、插件只声明、**都不写账本**。

**判据**：① **并发**：比对在动作的**服务端一半之前**（拒绝 ⇒ 账本/待办件**零新增**）；插件声明 `action.concurrency = {object_class, label, id_field|object_id, state}`，注册面**自动**加只读 `expected_version`；无记录 ⇒ 首次放行（记 `rev 1`）、对得上 ⇒ 放行、**内容会变或版本对不上 ⇒ 拒绝 `object-changed`** + `conflict.since`/`conflict.mine`；受保护三处 `quote.draft`/`exchange.change-respond`/`compare.save-weights`② **分享**（动作 `share.object`）：**不写账本/不落文件/不发邮件**（`ledger_added` 恒 `0`），产出**可复制深链** + **需求清单**（登录/侧/对方能不能看）+ **邮件正文**；"对方能不能看"由插件声明，**没声明不替它断言** ③ **导出列**：列是声明、**内容仍由插件生成**；列选择是按身份的偏好（`export-prefs.json`，0700/0600、有界）；**一列都不剩 ⇒ `report-columns-empty`**。

**禁止**：不得用锁/队列替代乐观并发（**不是锁定**）；分享与列选择不得写任何东西；越侧打开 / 未声明对象类要**如实拒**（`found:false` + 有名原因；`object-kind-not-in-this-view`）。
**真源**：`src/system/webui/docs/concurrency-and-sharing.md`（复跑 `python3 tmp/p9-verify.py`）。

## 15. 身份、会话与自助面（**业务动作的身份只认会话**）

**能力**：登录一次，之后每个动作的身份从服务端会话取（`human:<名字>`），不再手填；**登录/切换/登出**、**待我处理**、**人签**、**我的插件**四个自助面都在 APP 内。

**判据**：未登录 / 署名不符 / 替别人签 ⇒ `401`·`403`·`not-my-draft` 且**账本零新增**；越侧 ⇒ `side-mismatch`。
**人门必须被真正消费（P48）**：承诺 / 发 PO **只消费**一扇已 `granted`、且**不是署名者本人**批过的门（逐条判据见真源）；没有 ⇒ **具名拒** + 下一步、**账本零新增**；界面按账本如实写「谁批的 / 谁签的」（门没被用上**不装作有**）。**授权区间变更同口径**（P50：提交 → **另一人**复核 → 落盘，ADR-0025）。
**禁止**：不得再出现「用 URL 区分侧 / 手填 `--actor`」式入口；不得替别人签、不得回显凭据；**不得在同一次落账里自己开单自己批准**（自签自批只能由**默认关闭**的运营开关打开：`<ui-shared>/commitments/policy.json`，且界面与回执**如实写「批准人 == 署名人」**）。
**真源**：`src/system/webui/docs/identity-and-selfservice.md`（21 条身份路由 / 49 条断言含四条负控；**P48 人门判据见其 §人门**）。

## 16. 多人协作（指派 / 转交 / 关注 / 评论 `@` —— **不写账本**）

**能力**：同侧人类之间指派/转交/关注/评论 `@` 同事；工作台与 list 有「我的 / 我指派的 / 我关注的」筛选片。

## 20. 服务端窗口、性能与并发纪律

**能力**：长列表在"干一天活"的规模下可用（服务端窗口）；并发下不卡死（只读备忘 / 短 TTL / 渲染背压）；**写者之间显式互斥**。

**判据**（形状与读数 = 归档 §20）：① **窗口协议**：`/api/ui/panels`（`/api/ui/object` 同构）带 `w`/`pq`/`only` 走窗口，**没有就整份下发**；插件**照旧只实现 `data(ctx)`** ② **窗口的判据**：窗口里的行 = **全量 → 筛选 → 稳定全序排序 → 第 start..end 行**，与全量**逐行相同**；**全部派生计数在全集上算**③ **状态四态互不冒充**：加载 / 取新页（数字仍是上一次的）/ 错误（**绝不显示成空列表**）/ 空 ④ **并发纪律**：账本只读备忘按 `(路径, mtimeMs, size)`（落账必失效 ⇒ **不读旧值**）；通知聚合**短 TTL**（默认 5 s，动作/落待办件/清缓存**立刻失效**）；**渲染准入（背压）** 按事件循环**真实滞后**对新到的**重读**回 `429 + Retry-After`，**动作/身份/偏好/健康/静态一律不拒** ⑤ **唯一写者必须互斥**：写者之间 FIFO 票据 + 原子锁 ⇒ **同刻只有一个写者在写同一份账本**；批量进行中别人的**单条写排队**，**只读不排队**、动作**不被拒**。

**禁止**：性能**不得**换来错的数字（客户端不许自己算全集派生物）；不得把"取新页中"的旧数字冒充已更新；不得把"读不到"显示成"空"；不得把背压扩成拒动作/拒身份；不得用关功能换性能；**不得绕过写者闸门**（并发写同一份账本会毁链）。
**真源**：`src/system/webui/docs/{scale-and-performance,performance-under-concurrency,action-runtime-and-jobs}.md`（P11–P13 / P21）；实测读数见归档 §20.4。
