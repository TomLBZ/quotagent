## 1. 定义（唯一口径）

- **WebUI = 双方（承包商 / 供应商）的完整 GUI 应用**：像 VS Code 那样是一个**可长期使用的应用外壳**
  （窗口/导航/面板/编辑器/命令面板/通知/多视图/状态栏 + 快捷键 + 深链），像 DeepSeek harness 的 GUI 那样
  **用界面驱动真实流程**。它自己**不含业务语义**，但必须让**插件把自己的一切搬上界面**。
- **零业务语义 ≠ 零功能**：外壳提供机制（布局与槽位、命令与动作、表单与校验、通知与确认、导航与深链、
  状态与续跑、键盘与可访问性），**功能由插件注册进来**。
- **判定标准（这才是"完成"）**：承包商与供应商**仅通过 GUI**就能走完全部业务流程（见 §4），
  不需要打开终端、不需要手敲 `tools/verify.sh`；页面上每个动作都**真的落到账本/待办件**，
  且人工门（报价提交、授标承诺、下单、变更批准、价格让步）在界面上**可点、可等、可催、可签**。
- **允许前端框架**：可以用任何前端框架/构建产物；不因"零内联脚本"这类旧判据而拒绝交互能力
  （安全判据改成"脚本只来自受信来源 + 插件注册面"）。

2. 禁止用"页面结构锚点 / 快照 hash / 0 内联脚本"这类**没有交互**的判据冒充 UI 验收。

   与本文冲突，**删除**（引用链一并改干净），不要留在树里。
4. 禁止用"门禁全绿"当作进度汇报：**推进业务功能是唯一重要的事**；门只是安全带，不是目的。

## 3. 架构（机制在外壳，功能在插件）

- **外壳（`src/system/webui/code/`）**：应用壳（多视图/导航/命令面板/通知/快捷键/状态栏/深链）、
  **注册面**与装配器（0 插件 id、0 业务名词），以及把"界面事件 → 动作"接起来的**动作总线**。
- **注册面（插件往上挂的东西，至少这几类**，名字可按实现调整，语义不许缩水）：
  1. **视图 / 面板 / 区块**（placement、顺序、可见性条件）；
  2. **交互方式**（表单字段与校验、表格的编辑与批量操作、拖拽、右键菜单、键盘快捷键、内联动作）；
  3. **动作 / 命令**（`id` + 标题 + 入参 schema + 权限 + 确认策略 + 真调用哪个后端动作），可出现在
     命令面板、按钮、菜单、深链里；
  4. **业务逻辑钩子**：动作的**服务端一半**（插件自己的 Python/宿主实现）与**返回增量**（结果、
     待办件、需刷新哪些视图、需要什么人工确认）；
  5. **通知与状态**（进度、失败原因、next_action、待人工门队列）。
- **写路径不可绕过**：GUI 的动作只"发起"，凡对外承诺类动作仍必须经人工门与既有唯一写者
  （`tools/*-apply.py` 之类）落账本；GUI **不是**第二条事实写路径（这条与旧设计一致，保留）。
- **可撤销**：一切注册返回 disposer；插件卸载后其视图/动作/快捷键**全部消失**（AGENTS.md 规则 1）。

## 4. 双方完整业务流程（UI 必须覆盖，逐条可点）

- **承包商（业主侧）**：创建/发布 RFQ（含行项目、币种、截止、邀请供应商）→ 看谁收到/谁没回/还差多久 →
  催报与答疑（客户端提问、业主回答、广播）→ 收报价（归一化、偏差、护栏）→ 比价与排序（权重可调、
  贡献可解释）→ 人工门：批准/驳回/要变更 → 授标承诺（人签）→ 发 PO（逐行可追溯）→ 变更与价格让步
  （需批准）→ 审计与证据包（导出、验证）。
- **供应商（投标侧）**：看自己的 RFQ 包（只出自己那份）→ 提问/澄清 → 备报价（行项目/单价/交期/备注，
  草稿可续）→ 提交报价（人工门：签名）→ 谈判（承诺/反提案/接受）→ 承诺交期（产能日历、冲突提醒）→
  中标/落标通知与 PO 确认。
- **共同侧**：审批队列（等多久、卡在谁、可催办/升级/终止）、授权区间（谁能批多少）、
  比价 heuristics、截止看板、邮件通道状态、用户空间插件（自建视图）。
- **每一步都要能"在 APP 内闭环"**（含写操作），并且失败时给出**可复制的下一步**。

## 5. 落地路线（按用户优先级：先能用，再完善）

1. **P0（立刻做）**：应用壳 + 注册面（视图/动作/交互/通知）+ **一条真实闭环**（供应商侧：看包 → 备报价 →
   签名提交；承包商侧：发布 RFQ → 比价 → 批准 → 授标）。真起服务、真点、真回读账本。
2. **P1**：把剩余双方流程逐条搬进 GUI（答疑/催报/变更/PO/审计导出/审批队列/授权区间）。
3. **P2**：可用性打磨（键盘、命令面板、深链、空态与错误态文案、可访问性、多视图布局持久化）。
4. **用真实用户视角验收**：用 subagent 扮演"承包商采购员 / 供应商销售"走一遍，凡是"必须回终端才能做完"
   的步骤一律算 **UI 缺陷**，登记并修。

## 7. 台账与持久化（本批收口；口径以本节为准）

本节的五条都是**机制/口径**，不是新功能；它们各自回答「界面上的东西存在哪里、谁在判权限」：

1. **`/api/routes` 的 `auth` 是真实值**（不再写 `none` 撒谎）。凡落在 `${prefix}/contractor/` 或
   `${prefix}/supplier/` 下的**业务路由**一律标 `identity-session`——与路由级身份门槛
   （`code/identity.mjs#gateBusinessRoute`）**同一判据、按路径推导**（新增业务路由不会漏标）；`none`
   只留给**真的公开**的入口（总览/上手/健康/自述 JSON/GUI 外壳资源与注册面/运维与系统管理页自己判权限）。
   表里同时给 `auth_basis` 逐值解释。**别**再手抄一遍 `auth`：抄的会漂，推导的不会。
2. **通知偏好与已读在服务端**：`GET|POST ${prefix}/api/ui/notif-state`，按**会话身份**落
   `<ui_shared>/webui/notif-state.json`（目录 0700 / 文件 **0600**、原子写、有界：read ≤ 1000、静音 ≤ 50、
   身份 ≤ 64）。未登录 ⇒ 401（那时浏览器 localStorage 仍能用，但界面**如实说明**只在本浏览器有效）。
   它**不是账本事实**（偏好不是业务承诺）：换浏览器/换设备仍在，是因为读回同一份 0600 文件。
3. **邮件（SMTP/IMAP）通道有界面入口**：GUI 工作台首屏的「邮件通道」面板（`system/mail` 注册，
   `code/ui.mjs`）给出状态读数 + **界内配置表单**（表单 POST 到 `${prefix}/mail/config/`）；运维专页
   `${prefix}/ops/mail/` 也指向同一个入口。权限与落盘都不新造：运维侧身份 + 署名 == 会话身份 →
   `identity-mail-apply.py` → 唯一落盘者 `config-apply.py` 写 YAML（干跑 → 0600 待办件 → 落盘；
   凭据永不回显）。**`/workspace/config.yaml` 只读**（夹具验证时改的永远是夹具文件）。
4. **人签动作的服务端身份门**：`POST ${prefix}/api/action/<id>` 上，凡声明
   `permission: 'human-signature'` 的动作，**服务端**校验「已登录 + 入参 `signature` == 会话身份」
   （未登录 401 `identity-required` / 不一致 403 `signer-mismatch`，账本零新增）。界面**不代签、不写账本**：
   落账本的仍是既有唯一写者（`tools/quote-sign.py` 等）。
5. **一份报价 = 一次人签**（供应商侧）：可编辑表格**整张表一次提交** ⇒ 落**一条**草稿
   （`quote/drafted` 带逐行 `lines[]` + `line_count`），人签**一签提交整份**（`quote/submitted` 逐行给
   `lines[]`；多行报价没有「唯一那个行项目」，标量 `item_id`/`unit_price_cents` 留空/`null`）。
   单行报价的 body **逐字节不变**（仍 12 键）。缺行/改行一律**有名拒绝**：待办件被改 ⇒ `pending-tampered`、
   行项目不在事实里 ⇒ `line-item-not-found`、账本里的草稿自述与重算不符 ⇒ `draft-tampered`（三者账本零新增）。

## 8. 名册与角色：**「同事」= 名册里的人**（不是「登录过的人」），角色**限动作**而不是限视图

用户口径：「把『同事』从『登录过的人』变成**真名册与角色**」。本节的四条是**机制/口径**（判据在这一节里）：

1. **名册是权威取值处**：落 `<ui_shared>/people/roster.json`（目录 0700 / 文件 **0600**、原子写、有界：
   成员 200 / 角色 24；超出**如实拒**，不静默截断）。按**侧**分片（`side` 只由会话给，请求体改不动）。
   **它不进账本**：名册/角色/额度是**可改的运营配置**，不是合同事实（写进账本会改变事件类型目录、证据包哈希与
   审计取证语义，并会把"名册与额度"变成模型可见输入）。逐条理由写在 `code/people.mjs` 文件头。
2. **`@提及` / 指派 / 转交都从名册取值**：候选与校验同源（`GET /api/people/suggest` 是自动补全的服务端一半，
   字段声明 `suggest_url` / `mention_suggest_url` ⇒ 客户端出原生候选 / 正文里打 `@` 弹候选）；
   **未知名字如实拒**（`unknown-colleague`，回执里列出本侧名册；跨侧 `@` ⇒ `cross-side-mentioned`；
   名册外且没登录过的人**不假装通知到了**，进 `unresolved`）。**登录即登记**：一个名字第一次在某一侧登录 ⇒
   进名册、角色「待指派」（**有名字、没有权限**）；授权由同侧管理员在界面上补。
3. **按角色限动作**（服务端判据，在任何执行之前；拒绝时**账本与待办件零新增**）：
   · **转交别人的活**（`collab.assign` 已有人接手时）只有「**归我**」（当前指派给我）或「**我指派的**」
   （当前指派是我下的）能做，否则要 `policy.transfer.override_roles` 里的角色（默认 `supervisor`/`admin`）——
   拒绝码 `transfer-not-yours`；· **额度**（`policy.amount_limit.rules`：动作 id → 金额从**哪条事实**取 + 单位
   `major`/`minor`）超过**我角色**的 `approval_limit_cents`（整数分；`null`=不限，**`0` 与"不限"相反**）⇒
   `role-limit-exceeded`，回执给出金额/我的额度/**该找哪个角色**；金额取不到按 `unknown_amount`（默认 `refuse`）。
4. **角色不改变签署权**（结构性）：额度/角色判据跑在「署名 == 会话身份」**之后**、插件自己的服务端一半**之前**
   —— 它**只能否决、不能放开**；角色再高也不能替别人签，也不能跳过人工门（§7.4 的人签门一字未动）。
   名册维护本身也按角色判：本侧**还没有管理员**时谁都能先配（bootstrap，界面如实说明）；有了管理员之后，
   改人/改角色/改策略**只有管理员**（`admin-required`）—— 免得采购员自己把自己升上去。

## 9. 通知偏好 / 已读 / **布局** / 筛选：**整份**服务端化（按身份）

1. `GET|POST ${prefix}/api/ui/notif-state`（`POST` 整体替换）：已读集合、静音的插件、最低级别、**面板布局
   （顺序/折叠/隐藏，按「视图+对象类」分桶）**、筛选片选择，**全部**落 `<ui_shared>/webui/notif-state.json`
   （目录 0700 / 文件 **0600**、原子写、有界、洗净 —— 形状不对的**丢掉并如实计数**在 `dropped` 里）。
2. **按会话身份隔离**：换浏览器、换设备读回同一份（这就是"跨设备仍在"）；身份之间互不可见；未登录 ⇒ 401
   `identity-required`（那时界面如实说明"只在本浏览器有效"，localStorage 降为**离线镜像**）。它**不是账本事实**。
3. **只读路由的方法围栏**：只应为 `GET` 的路由（含 `/api/collab/{hub,object,store}`、
   `/api/people/{roster,suggest,store}`）收到非 GET ⇒ **405 + `method-not-allowed` + 响应头 `Allow: GET`**，
   且**先按方法判据拒绝、再做身份校验**（顺序反了会变成 401，"只读路由不接受写"这条契约就失效）。
   机检：`tools/verify.sh quote-draft` 第 ③ 条（拿 `/api/routes` 逐条 POST：**判据按路径推导**，
   新增只读路由不必也不会有人手抄一遍）。

用法、配置与边界见 `src/system/webui/docs/people-and-roles.md`；复跑 `python3 tmp/p5-people-verify.py`。
