# 10 非功能需求

<!-- budget: 16 KB. 标注: [假设]=待现场验证；目标值一律待 P0 基线后由人设定 -->

## 1. 可靠性与一致性

| ID | 需求 | 检验 |
|---|---|---|
| NFR-REL-001 | 任何进程崩溃后，账本中已追加的事实零丢失 | 崩溃注入测试（P1） |
| NFR-REL-002 | 重启后系统状态 = 账本重放结果（不含未落账草稿） | 重放一致性检查 |
| NFR-REL-003 | 报文投递采用至少一次 + 幂等 = 实际一次 | 重复投递测试（AC-QEP-002） |
| NFR-REL-004 | 卸载插件后无残留订阅/定时器/外部通知 | INV-002 |
| NFR-REL-005 | 一方离线不得阻塞另一方的本地推进（对外步骤挂起即可） | 离线场景测试 |

## 2. 幂等与并发

| ID | 需求 |
|---|---|
| NFR-IDEM-001 | `msg_id` + `body_hash` 唯一确定一条事实；重复到达不产生第二条 |
| NFR-IDEM-002 | 同一核对步骤可安全重跑（投影、归一化、比价均为纯函数语义） |
| NFR-IDEM-003 | 并发修改同一实体由账本追加顺序决定，冲突走 `03` §4，不做隐式覆盖 |
| NFR-IDEM-004 | 状态跃迁幂等：重复提交同一意图不产生双重承诺（承诺类另有批准去重键） |

## 3. 性能预算 [假设]

| ID | 目标 | 说明 |
|---|---|---|
| NFR-PERF-001 | 归一化 + 比价 ≤ 30 s（200 条目 × 5 报价，本机单进程） | P0 采集真实基线后修订 |
| NFR-PERF-002 | 账本追加 ≤ 5 ms / 事件（本地文件，含 fsync） | |
| NFR-PERF-003 | 投影重建 ≤ 10 s / 10^4 事件 | 全量重建；增量应显著更快 |
| NFR-PERF-004 | 单次模型调用 ≤ 60 s，token 上限由策略 patch 设定 | 超时即失败，不静默降级 |

**原则**：预算不达标时优先"拒绝服务并告警"，而不是"降级精度悄悄算"（P8）。

## 4. 可用性

| ID | 需求 |
|---|---|
| NFR-UX-001 | 所有人工门必须以队列呈现，不阻塞 agent 其他工作 |
| NFR-UX-002 | 每条待批项必须显示：动作、payload 摘要、引用链、风险 Flag |
| NFR-UX-003 | 供应商侧界面不得暴露承包商私域任何字段（含间接暗示） |
| NFR-UX-004 | 报价草稿支持离线编辑，恢复后可继续（草稿丢失不报错） |

## 5. 可维护性与可演进性

| ID | 需求 |
|---|---|
| NFR-MNT-001 | 新增能力必须是插件 + 接缝三角；禁止改内核实现业务逻辑 |
| NFR-MNT-002 | 所有配置变化可从 patch 层追溯（哪一层、哪一条） |
| NFR-MNT-003 | 每个非平凡改动附一条设计记录（ADR 或设计小节更新） |
| NFR-MNT-004 | 文档预算受检（`12`），超预算先压缩表达 |
| NFR-MNT-005 | 代码与文档同批提交，不允许"文档以后补" |

## 6. 兼容与迁移

| ID | 需求 |
|---|---|
| NFR-COMPAT-001 | QEP 版本不兼容即显式拒绝，不静默降级（`03` §6） |
| NFR-COMPAT-002 | 账本事件类型只增不改语义；语义变更 = 新类型 + ADR |
| NFR-COMPAT-003 | 旧版本账本永远可读（只读归档，不改写历史） |
| NFR-COMPAT-004 | 供应商侧与承包商侧可独立升级；升级窗口内的报文按版本并存处理 |

## 7. 合规与留存

| ID | 需求 |
|---|---|
| NFR-COMP-001 | 审计包可导出并独立验证（哈希链 + 签名） |
| NFR-COMP-002 | 模型输入可重建（P4），重建失败即为合规缺陷并告警 |
| NFR-COMP-003 | 留存期与销毁策略由项目 patch 配置；销毁动作本身留痕 |
| NFR-COMP-004 | 不做任何"模型替代人类签署"的功能，即使被要求 |

## 8. 规模假设（与 `02` §6 一致）

单包条目 ≤ 2000 · 单包投标人 ≤ 50 · 单项目事件 ≤ 10^6 · 报价版本 ≤ 20/包 ·
同时活跃项目 ≤ 50 · 单项目参与者 ≤ 200。全部为 `[假设]`，超出即先扩容量再上线。

## 9. 环境与依赖

- 实现栈在 P0 启动时确定并记入 ADR（默认为 Python 3.12+，理由：与既有工具链一致、生态成熟）。
  `[假设]` 若团队已有 TS/Node 基础设施，可改；ADR-0001 只约束"借鉴设计而非 vendor 代码"。
- 不依赖任何必须联网的组件才能跑通 P0/P1（离线可用是硬要求，见 NFR-REL-005）。
- 本地优先：默认部署为单机双进程 + 共享目录投递，不强制引入消息中间件。
