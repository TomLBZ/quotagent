# 08 信任、隔离与安全

<!-- budget: 20 KB. 标注: [假设]=待现场验证 -->

## 1. 信任模型（先讲清楚谁不信谁）

| 关系 | 假设 | 后果 |
|---|---|---|
| 承包商 ↔ 供应商 | **互不信任**，但需要协作 | 所有交换内容签名；私域数据不出本侧 |
| 同一方内部的 agent ↔ 人 | agent 不可信其"承诺能力" | 承诺必须人工批准 |
| agent ↔ agent（同一方内） | 可信但会出错 | 输出必须带引用；越界即拦 |
| relay ↔ 双方 | relay 可不可信均不影响语义 | relay 只见信封与密文载荷；可替换为共享目录/邮件 |
| 模型提供商 | 模型调用可能外泄上下文 | 私域字段在出站前脱敏；详见 §4 |

`[假设]` 实际商务谈判中双方可能愿意在受控条件下共享部分成本信息（如"价格构成合理性"）。
本设计把这列为**可选、自愿、人工批准**的能力，不作为默认行为。

## 2. 隔离的三层

```
第 1 层  进程/容器隔离：两侧运行时不同进程、不同文件系统路径、不同环境变量
第 2 层  realm 隔离：ctx.* 服务按参与方/项目/标段分域，跨域取值直接失败（INV-008）
第 3 层  密钥隔离：签名密钥各自持有，relay 与对方均无本侧私钥
```

**必须记住的边界**：realm 是**命名空间**语义，不是安全边界
（`../analysis/cordis-architecture.md` §6.4 明确指出 Cordis 不隔离不受信代码）。
真正的安全来自第 1、3 层。任何把 realm 当沙箱的用法都是错误实现。

## 3. 数据分类与流向

| 类别 | 例子 | 可否出 realm | 可否进模型 | 备注 |
|---|---|---|---|---|
| Public | 公开价格表、公开规范 | ✔ | ✔ | |
| Exchange | 包范围、清单、报价、偏差、交期、条款 | ✔（经 QEP） | ✔ | 交换范围由协议固化 |
| Private-contractor | 标底、内部评分、其他投标人报价 | ✘ | ✔（仅本侧模型） | 泄露即重大事故 |
| Private-supplier | 成本构成、利润率、产能日历、竞争情报 | ✘ | ✔（仅本侧模型） | 同上 |
| Regulated | 审批记录、签名、审计包 | 按协议 | ✘（不进模型） | 只存证，不参与推理 |

**操作规则**

1. 附件正文（PDF/Excel 原文）**不进提示词**（`06` §3 规则 3），只进哈希与抽取字段。
2. 出站报文在发送前做一次分类扫描：出现 `Private-*` 字段即拒绝发送并产 `guard/private-leak` 事件。
3. 进模型前的上下文由投影器生成，投影器按 realm 过滤——不是"提示词里写了别泄露"，
   而是**数据根本不出现**。

## 4. 模型侧风险

| 风险 | 对策 | 检验 |
|---|---|---|
| 上下文外泄（供应商看到标底） | 私域字段在进模型前已被投影器过滤 | AC-TRUST-001 |
| 提示注入（报价正文含指令） | 正文不进上下文；结构化字段白名单 | AC-GUARD-003 |
| 模型被诱导越权调用工具 | 工具入口的 realm 校验 + 承诺旁路禁止 | INV-008 / AC-APPROVE-002 |
| 模型输出被当作权威 | 输出只有 Intent；承诺走人工门 | INV-005 |
| 训练/日志留存导致二次泄露 | 日志只存引用与哈希；正文加密存储 | AC-AUDIT-003 |

## 5. 对抗性报价与异常行为

| 模式 | 检测 | 处置 |
|---|---|---|
| 异常低价（可能漏项或后期索赔） | `guard.abnormal_low`：与同包其他报价/历史同类条目比较 | Flag + 强制人工复核，**不自动否决** |
| 漏项（对某些条目不报） | 清单对齐检查 `missing_item` | Flag + 要求澄清，未澄清不得评为可比 |
| 虚假产能 | `capacity` 与历史履约数据交叉 | Flag + 交期承诺降级为 `indicative` |
| 条款暗坑（罚则/质保不对等） | `terms.conflicts` | Flag + 条款冲突必须人工裁决 |
| 报价正文注入指令 | 正文隔离 + 异常文本检测 | 拒绝该字段进入上下文，保留原文供人审 |
| 单方伪造对方批准 | 批准记录各自本地产生，承诺需两侧各留记录 | `03` §4.4 |

`[假设]` 异常低价阈值的合理取值需现场数据校准；P0 只记录基线，不设判定结论。

## 6. 密钥与审计

- 每方一对 Ed25519 密钥；私钥仅存本侧，权限 0600，不入库（`.gitignore` 已覆盖 `*.local.yaml`）。
- 密钥轮换：`participant/key-rotated` 报文宣告；旧公钥保留一个过渡期用于验签历史。
- 账本哈希链 + 定期 `evidence/pack`（含 Merkle 根）构成可验证留存。
- 留存期与销毁策略由项目 patch 配置（合规要求因地域而异，`[假设]` 需现场确认）。

## 7. 威胁清单（简版 STRIDE 映射）

| 威胁 | 场景 | 缓解 |
|---|---|---|
| Spoofing | 伪造对方身份发报价 | 签名 + 密钥隔离 |
| Tampering | 事后改账本条目 | 哈希链 + `verify_chain` |
| Repudiation | 否认曾承诺 | 双方各留批准记录 + 签名报文 |
| Information disclosure | 标底/成本外泄 | 三层隔离 + 投影过滤 + 出站扫描 |
| Denial of service | 一方离线阻塞对方 | 异步队列 + 本地可继续推进（`03` §7） |
| Elevation of privilege | agent 绕过人工门 | 唯一对外出口校验批准链 |
