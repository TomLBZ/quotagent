# 11 集成图（外部系统接入与降级路径）

<!-- budget: 14 KB. 原则：每一项接入都必须有"无外部系统"的降级路径，否则它不能进 P0/P1 -->

## 1. 接入清单

| 外部系统 | 用途 | P0 | P1 | P2 | 降级路径（无该系统时） |
|---|---|---|---|---|---|
| 本地文件系统 | 账本、附件、报文投递 | ✔ | ✔ | ✔ | 无（基础） |
| 共享目录 / 同步盘 | 双方报文投递 | ✔ | ✔ | ✔ | 邮件附件投递 |
| 邮件（IMAP/SMTP） | 收发澄清与报价通知 | – | 可选 | ✔ | 人手动粘贴报文文本 / 文件投递 |
| HTTP relay | 可靠投递 + 存证 | – | 可选 | ✔ | 共享目录；语义完全相同（`03` §8） |
| 供应商门户（Web） | 供应商界面 | – | – | ✔ | CLI + 文件投递 |
| ERP（订单/条目） | PO 与主数据对齐 | – | – | ✔ | 导出 CSV 人工导入 |
| 造价库 / 单价参考 | 市场参考价 | – | 可选 | ✔ | 历史中标价（本 realm 账本内） |
| 汇率源 | 多币种折算 | – | 可选 | ✔ | **人工录入汇率时点值**（不得静默用旧值） |
| 图纸/PDF 解析 | 规格引用抽取 | – | 可选 | ✔ | 人工录入结构化字段（模型只做建议） |
| 文件存储/对象存储 | 附件与证据包 | – | 可选 | ✔ | 本地目录 + 哈希清单 |

**判定规则**：一个接入点进入某阶段的前提是它的**降级路径已被验证可用**。
这条规则保证系统在没有任何外部集成时依然完整可跑（也是 P0 mock 能成立的原因）。

## 2. 数据流边界

```
外部系统 ──(1)──▶ 接入适配器 ──(2)──▶ 结构化字段 ──(3)──▶ ctx.norm ──(4)──▶ 账本事实
                                     └─(2')─▶ 附件引用（哈希 + 类型，正文不进上下文）
```

1. 适配器只做"搬运 + 格式转换"，**不做业务判断**（判断在 `norm` 与 `guard`）。
2. 所有进入系统的数据必须有来源标记（`source∈{manual, mail, portal, erp, ...}` + 时间 + 操作者），
   以便审计时区分"人录"与"系统取"。
3. 无法结构化的内容一律走 (2') 引用路径，不进入模型上下文（`08` §3 规则 1）。

## 3. 与既有工具的共存策略

| 既有做法 | 共存方式 |
|---|---|
| Excel 比价表 | 系统产出可导出为 Excel/CSV 的比价表；不要求人放弃现有习惯 |
| 邮件往返 | 系统生成"可直接人工转发的报文文本"；对方未接入时人当传输层 |
| 内部台账 | 通过导出适配器对齐，而非要求迁移到系统账本 |

**原则**：先做"在既有流程里插一层一致性"，再做"替换既有流程"。原因：采购流程的
组织阻力大于技术阻力，`[假设]`这一点需现场验证。

## 4. 关键接缝的实现优先级

1. `file-drop`（P0）：目录约定 + 文件命名 + 原子写（写临时文件再 rename）。
2. `http-relay`（P1）：只存证与转发，不解析 body；可托管在任一侧或第三方。
3. `mail-bridge`（P2）：把报文作为附件 + 正文摘要；需要处理编码、大小限制、退信。
4. `erp-sync`（P2）：只做读写两个方向的最小字段集（PO 号、条目号、数量、单价）。

## 5. 失败与降级行为（必须显式）

| 失败 | 行为 |
|---|---|
| 汇率源不可用 | `pricing` 失活（依赖缺失）→ 拒绝出价；人工录入后恢复 |
| relay 不可达 | 排队 + 指数退避重试；超过阈值通知人；本地继续可做的工作 |
| 邮件发送失败 | 保留草稿；不落账为"已发送"（避免账实不符） |
| ERP 字段映射失败 | 明确报错并保留原始记录；不猜测映射（P8） |
| 附件解析失败 | 标记为待人工处理；不影响其他条目的推进 |
