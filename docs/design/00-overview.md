# 00 总览

<!-- budget: 16 KB -->

## 1. 一句话

**quotagent 是一个双边的、账本驱动的采购-报价协作系统**：承包商侧与供应商侧各自运行一个
agent 运行时，双方通过追加式账本与 QEP 协议交换事实与意图，所有对外承诺由人批准，
系统的组成与策略以可编辑数据形式存在、可热插拔、可在线自进化。

## 2. 设计原则（编号在文档间被引用）

| 编号 | 原则 | 直接后果 |
|---|---|---|
| P1 | **内核不可自进化** | 账本、事件分发、协议版本由人类变更；agent 只能改外围插件与配置 |
| P2 | **事实追加 / 意图可变 / 承诺人签** | 三分类贯穿数据模型、协议与 UI（ADR-0004） |
| P3 | **一切注册可撤销** | 任何新能力以 effect 注册并返回 disposer；无不可卸载的全局状态 |
| P4 | **模型可见即可审计** | 进入模型输入的每条事实都能从账本重建（AGENTS.md 规则 2） |
| P5 | **隔离即主权** | 一方内部数据（成本模型、标底、评分）在另一方的 realm 中取不到值 |
| P6 | **归一化在边界，不在决策里** | 币种/税率/单位/计量规则在进入比价前必须已归一，否则拒绝进入（fail loud） |
| P7 | **冲突有权威方且留痕** | 字段级归属矩阵 + 冲突上报事件，不做静默覆盖（ADR-0003） |
| P8 | **人门在承诺处，不在计算处** | 计算尽量自动，签字必须有人；人工门不阻塞异步流程 |

## 3. 三层结构（与 Cordis 范式对应）

```
L0 内核（人类所有）         L1 能力接缝（可插拔、可自进化）      L2 装配与交互面
ctx.ledger  追加式账本      承包商: rfq / compare / award         profile: contractor-ops
ctx.events  五模式分发      供应商: intake / costmodel / pricing  profile: supplier-bid
ctx.plugin  装载与生命周期   共享:   norm / clarify / negotiate    profile: relay
ctx.qep     协议与信封校验  治理:   approval / guard / evidence   profile: evaluator
                                自动化: eval / evolve             交互: CLI / Web / 邮件 / 文件
```

- **L0 对应 Cordis 的 core**：小、稳定、被完整理解（`docs/analysis/cordis-design-strengths.md` 优势 7）。
  内核只有四件事：账本、装载、事件、协议版本。
- **L1 对应 Cordis 的插件**：每项能力都是 Service Definition / Provider / Consumer 三角
  （优势 5，接缝三角见 `04-services-catalog.md`）。
- **L2 对应 Cordis 的 loader + patch 分层**：装配是数据（优势 5），自进化就发生在这一层（`07`）。

## 4. 术语（本仓库内的确定含义）

| 术语 | 含义 | 不要混淆 |
|---|---|---|
| **事实 (Fact)** | 已发生的、不可变的观察，只可追加 | 不等于"真值"；是"已记录且无争议" |
| **意图 (Intent)** | 单方声明、可撤回、可变的状态 | 不构成任何商业承诺 |
| **承诺 (Commitment)** | 双方确认后不可变的义务，只能追加更正条目 | 必须有人工批准记录 |
| **账本 (Ledger)** | 每方本地的 append-only 事件序列 + 投影 | 不是数据库表；投影可重建 |
| **realm** | 隔离域：一方/一项目/一标段的服务命名空间 | 不是安全边界（安全靠进程与密钥，见 `08`） |
| **QEP** | Quote Exchange Protocol，双方交换报文的协议 | 传输无关；信封语义唯一（`03`） |
| **seam（接缝）** | 一组 Definition/Provider/Consumer 组成的可替换能力 | 只有一个角色时不构成接缝 |
| **人工门 (Human Gate)** | 必须人签字才能推进的检查点 | 不等于"人工审批全部" |

## 5. 非目标（本设计不做）

1. 不做法定招投标平台的程序替代，只做协作与一致性层。
2. 不做工程量计算/图纸识别的正确性担保（模型产出为建议，人签）。
3. 不做支付、发票开具、税务申报。
4. 不做供应商征信与资质司法判定。
5. 不做"AI 自动授标"——排序可以自动，选择必须人签。

## 6. 成功判据（分阶段，避免过度承诺）

- **P0**：单一仓库内、单进程、纯文件账本，跑通
  `RFQ v1 → 澄清 1 轮 → 2 份报价 → 归一化 → 比价表` 的确定性重放（同输入同输出）。
- **P1**：双侧两个进程 + QEP over 文件/HTTP relay，跑通完整链路含版本变更、偏差表、
  异常低价护栏、审批门、账本重放与审计包导出；3 个场景集全部 AC 通过。
- **P2**：多租户部署、真实外部系统接入（邮件/文件/ERP 择二）、自进化流水线（影子→门→canary）、
  可观测性与留存合规。

指标定义见 `docs/analysis/domain-painpoints.md` §4；**目标值一律待 P0 采集基线后由人设定。**
